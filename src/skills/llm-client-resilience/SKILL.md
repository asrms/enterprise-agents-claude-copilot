# Skill: LLM Client Resilience

## Implementation Rules:
- **[ARCHITECTURE]** Provider-agnostic port in `app/domain/llm/ports.py`: `class LLMGateway(Protocol)` with `async def complete(self, request: LLMRequest) -> LLMResponse` and `def stream(self, request: LLMRequest) -> AsyncGenerator[StreamChunk, None]` (declared `def` in the Protocol, implemented as `async def` with `yield`); `LLMRequest`, `LLMResponse`, and `StreamChunk` are domain models, never provider SDK types.
- **[ARCHITECTURE]** Adapters in `app/infrastructure/llm/` (`AnthropicGateway` on `anthropic.AsyncAnthropic`) and decorators implementing the same Protocol, composed in the wiring: `ResilientLLMGateway` (circuit breaker, fallback, metrics) → `CachingLLMGateway` → adapter. The adapter translates SDK exceptions into domain errors: `LLMUnavailableError` (retryable errors exhausted, deadline), `LLMRequestError` (4xx), `LLMTruncatedError`.
- **[MANDATORY]** Primary model, `fallback_model`, `max_tokens`, temperature, timeouts, and prices come from `Settings` (`settings.llm.model`, `settings.llm.fallback_model`); no model identifiers (`"claude-..."`) in application code, only in configuration and test fixtures.
- **[CONFIGURATION]** SDK client created once in the lifespan: `AsyncAnthropic(api_key=settings.llm.api_key.get_secret_value(), timeout=httpx.Timeout(settings.llm.timeout_s, connect=5.0), max_retries=0)` and closed with `await client.close()`; `max_retries=0` because retries are handled by tenacity (the SDK default is 2 and would multiply the attempts).
- **[MANDATORY]** Timeouts on two levels: an HTTP timeout per single call (connect/read) and an overall deadline `async with asyncio.timeout(settings.llm.deadline_s)` that includes all retries and backoffs; on expiry `LLMUnavailableError` is raised.
- **[PATTERN]** Retry with `tenacity.AsyncRetrying(retry=retry_if_exception(is_retryable), stop=stop_after_attempt(settings.llm.max_attempts), wait=wait_exponential_jitter(initial=0.5, max=settings.llm.max_backoff_s, jitter=1.0), before_sleep=before_sleep_log(logger, logging.WARNING), reraise=True)`; 3-4 total attempts is the typical ceiling for synchronous user requests.
- **[MANDATORY]** `is_retryable(exc)` returns `True` only for `anthropic.APIConnectionError` (which includes `APITimeoutError`) and for `anthropic.APIStatusError` with `status_code` in `{408, 409, 429, 500, 502, 503, 504, 529}` (529 = overloaded); never retry on 400, 401, 403, 404, 413, 422.
- **[PATTERN]** On 429/529 honor the `retry-after` header (`exc.response.headers.get("retry-after")`) with a custom `wait` strategy that uses the maximum of the header and the exponential backoff, capped by `max_backoff_s`; if the wait exceeds the remaining deadline, fail immediately.
- **[PATTERN]** Circuit breaker per provider/model, one instance per process created in the lifespan: CLOSED → OPEN after `failure_threshold` consecutive retryable errors, HALF_OPEN after `recovery_timeout_s` measured with `time.monotonic()` with a single probe call; with the circuit open, switch to the fallback or respond 503 without contacting the provider. 4xx errors do not open the circuit.
- **[PATTERN]** Fallback model from config used only with the circuit open or retries exhausted on the primary, never for 4xx errors (an invalid prompt would also fail on the fallback, doubling costs); `LLMResponse.model` reports the actual model and metrics distinguish `route="primary"` from `route="fallback"`.
- **[MANDATORY]** `max_tokens` always explicit per use case and read from config; input checked before the call with `await client.messages.count_tokens(model=..., system=..., messages=...)` or with a conservative estimate, daily per-tenant budget in Redis; `stop_reason == "max_tokens"` handled explicitly with `LLMTruncatedError`, never returned as silent partial output.
- **[PATTERN]** Streaming with `async with client.messages.stream(model=..., max_tokens=..., system=..., messages=...) as stream:` and `async for text in stream.text_stream: yield StreamChunk(text=text)`, then `await stream.get_final_message()` for `usage` and `stop_reason`; toward the client `StreamingResponse(media_type="text/event-stream")` with `delta`, `done`, and `error` events.
- **[FORBIDDEN]** Retrying a stream after the first chunk has been sent to the client (it would duplicate text and costs): retry applies only to opening the stream; afterwards emit an in-band `event: error` (the 200 status has already been sent). The generator must be consumed in `contextlib.aclosing(...)` to close the upstream connection when the client disconnects.
- **[PATTERN]** Structured output forced with tool use (`tools=[{"name": "record_triage", "description": ..., "input_schema": TriageDecision.model_json_schema()}]`, `tool_choice={"type": "tool", "name": "record_triage"}`) or with native structured outputs when supported by the SDK and model version in use; always validate with `TriageDecision.model_validate(...)` and on `ValidationError` retry at most `settings.llm.max_validation_retries` (1-2) times reporting the error back to the model, then `LLMOutputInvalidError`.
- **[PERFORMANCE]** Cache deterministic responses (`temperature=0`, same model and same `prompt_version`) in Redis with a SHA-256 key of `model|prompt_version|tenant_id|system|messages|max_tokens` and a TTL from config; never a cache shared across tenants or for responses containing personal data.
- **[PERFORMANCE]** Provider prompt caching for long, stable system prompts: `system=[{"type": "text", "text": SYSTEM_PROMPT, "cache_control": {"type": "ephemeral"}}]`; verify effectiveness with `usage.cache_creation_input_tokens` and `usage.cache_read_input_tokens`.
- **[MANDATORY]** Metrics for every call: `Histogram("llm_request_duration_seconds", ..., ["route"])` observed with `.time()` even when the call fails, `Counter("llm_tokens_total", ..., ["model", "direction"])`, `Counter("llm_cost_usd_total", ..., ["model"])` with cost computed from `usage` and per-million-token prices taken from config, plus time-to-first-token for streaming; low-cardinality labels (never `user_id` or `request_id`).
- **[CONFIGURATION]** OpenTelemetry tracing with the GenAI attributes (`gen_ai.request.model`, `gen_ai.usage.input_tokens`, `gen_ai.usage.output_tokens`): the GenAI semantic conventions are still experimental, so pin the version of the instrumentation libraries.
- **[SECURITY]** Log every call with `request_id`, model, tokens, latency, number of attempts, and outcome; prompts and responses never in plaintext in production logs (only SHA-256 hash and length).
- **[TESTING]** Retry policies tested with respx on the `https://api.anthropic.com/v1/messages` endpoint (`side_effect=[httpx.Response(529, json=...), httpx.Response(200, json=...)]`) or with fakes that raise `anthropic.RateLimitError("rate limited", response=httpx.Response(429, request=request), body=None)`; verify `call_count` for 429/5xx/529 and the absence of retries for 400/401, with `max_backoff_s=0` in the test settings.
- **[REFERENCE]** See `EXAMPLES.md` in this folder for reference anti-patterns and best practices.
