# Skill: Asynchronous Processing, Events, and Messaging in Spring Boot

## Implementation Rules:
- **[MANDATORY]** Every `@Async` must specify an explicit executor (`@Async("invoiceExecutor")`) defined as a `ThreadPoolTaskExecutor` bean with `corePoolSize`, `maxPoolSize`, a bounded `queueCapacity` (never the default `Integer.MAX_VALUE`), `threadNamePrefix`, `setWaitForTasksToCompleteOnShutdown(true)`, and `setAwaitTerminationSeconds(30)`.
- **[CONFIGURATION]** With Java 21 and Spring Boot 3.2+ enable virtual threads with `spring.threads.virtual.enabled=true` for I/O-bound workloads: the auto-configured `applicationTaskExecutor` becomes a `SimpleAsyncTaskExecutor` on virtual threads; limit concurrency toward scarce resources with `spring.task.execution.simple.concurrency-limit` or a `Semaphore`, never with a pool of virtual threads.
- **[PERFORMANCE]** On virtual threads avoid `synchronized` blocks around blocking I/O on JDK 21 (they cause carrier thread pinning, fixed in JDK 24 with JEP 491): use `ReentrantLock` and diagnose with `-Djdk.tracePinnedThreads=full`; remember that HikariCP remains the bottleneck and must be sized accordingly.
- **[FORBIDDEN]** Do not invoke an `@Async`, `@Transactional`, or `@Retryable` method from the same class (self-invocation): the call bypasses the AOP proxy and runs synchronously; move the method to a separate bean and inject it.
- **[PATTERN]** `@Async` methods return `void` or `CompletableFuture<T>` (never a raw `Future`); for `void` methods register an `AsyncUncaughtExceptionHandler` via `AsyncConfigurer#getAsyncUncaughtExceptionHandler()`, otherwise exceptions are only logged.
- **[PATTERN]** Compose parallel calls with `CompletableFuture.supplyAsync(task, executor)` always passing the executor (never the `ForkJoinPool.commonPool()`), applying `orTimeout(...)` and `exceptionally(...)`/`handle(...)`; do not call `join()`/`get()` without a timeout on request threads.
- **[MANDATORY]** Propagate context into async threads with `executor.setTaskDecorator(...)`: copy `MDC.getCopyOfContextMap()` and the `SecurityContext` (or use Spring Framework 6.1+'s `ContextPropagatingTaskDecorator` with Micrometer context-propagation for MDC and tracing, and `DelegatingSecurityContextAsyncTaskExecutor` for security), always clearing the context in the `finally` block.
- **[PATTERN]** React to domain events with `@TransactionalEventListener(phase = TransactionPhase.AFTER_COMMIT)` for non-transactional side effects (emails, caches, notifications); if the listener writes to the DB annotate it with `@Transactional(propagation = Propagation.REQUIRES_NEW)` (Spring 6.1+ rejects other propagations on transactional listeners).
- **[FORBIDDEN]** Do not publish to Kafka/RabbitMQ or call external services inside a DB transaction (`kafkaTemplate.send()` inside `@Transactional`): it produces inconsistent dual writes on rollback or on a crash after commit.
- **[ARCHITECTURE]** Guarantee delivery of integration events with the Transactional Outbox: save the event in the `outbox_event` table in the same transaction as the aggregate and publish it with a relay (polling with `SELECT * FROM outbox_event WHERE published_at IS NULL ORDER BY id LIMIT 100 FOR UPDATE SKIP LOCKED` or Debezium CDC), or with Spring Modulith's Event Publication Registry (`spring-modulith-events-jpa`).
- **[MANDATORY]** Make every Kafka consumer idempotent: deduplicate with a `processed_message` table with a `UNIQUE(message_id)` constraint inserted in the same transaction as the business effect, or with naturally idempotent operations (versioned upserts); delivery is at-least-once.
- **[PATTERN]** Handle consumer errors with `@RetryableTopic(attempts = "4", backoff = @Backoff(delay = 1000, multiplier = 2.0), exclude = {ValidationException.class, DeserializationException.class})` and a `@DltHandler` method, or with `DefaultErrorHandler` + `DeadLetterPublishingRecoverer` + `ExponentialBackOffWithMaxRetries`; non-recoverable exceptions go straight to the DLT.
- **[CONFIGURATION]** Configure Kafka clients safely: producers with `acks=all` and `enable.idempotence=true`, consumers with `enable-auto-commit=false`, `spring.kafka.listener.ack-mode=record` (or a deliberate `batch`), `ErrorHandlingDeserializer` wrapping the deserializer, and `spring.json.trusted.packages` listed explicitly (never `*`).
- **[PATTERN]** Use a Kafka message key equal to the aggregate id (`orderId`) to guarantee per-entity ordering within the same partition; include `eventId`, `eventType`, and `traceparent` in the headers.
- **[MANDATORY]** In multi-instance deployments protect every `@Scheduled` with ShedLock: `@EnableSchedulerLock(defaultLockAtMostFor = "PT10M")`, `@SchedulerLock(name = "invoiceReminderJob", lockAtMostFor = "PT5M", lockAtLeastFor = "PT30S")`, and a `JdbcTemplateLockProvider` configured with `.usingDbTime()`.
- **[CONFIGURATION]** Express crons with an explicit zone (`@Scheduled(cron = "${jobs.invoice-reminder.cron}", zone = "Europe/Rome")`), size `spring.task.scheduling.pool.size` (default 1), and keep the scheduled method short by delegating to a use case.
- **[SECURITY]** Do not propagate the user `SecurityContext` to scheduled jobs or consumers: run with an explicit technical identity and do not serialize tokens or personal data into event payloads beyond the necessary minimum.
- **[TESTING]** In async tests use Awaitility (`await().atMost(Duration.ofSeconds(10)).untilAsserted(...)`) instead of `Thread.sleep`, and real Kafka via Testcontainers (`KafkaContainer` or `ConfluentKafkaContainer` with `@ServiceConnection`) to verify retry, DLT, and idempotency with duplicate messages.
- **[PERFORMANCE]** Expose executor metrics (`executor.active`, `executor.queued`) and consumer metrics (`spring.kafka.listener.observation-enabled=true`) and set alerts on consumer lag and outbox table growth.
