# Skill: Web Components with Custom Elements and Shadow DOM

## Implementation Rules:
- **[MANDATORY]** Custom element name with a hyphen and a project prefix (`acme-date-picker`; a name without a hyphen makes `customElements.define()` throw a `SyntaxError`); idempotent registration with `if (!customElements.get(name)) customElements.define(name, Ctor)`; one component per folder in `src/components/<name>/<name>.js`.
- **[FORBIDDEN]** Customized built-in elements (`class extends HTMLButtonElement` with `is="acme-button"`), not supported by Safari: always extend `HTMLElement` and use native elements inside the shadow root.
- **[FORBIDDEN]** In the `constructor`, reading or setting the host's attributes and children, running `fetch`, starting timers, or registering listeners on `window`/`document`: the specification forbids adding attributes or children (with `document.createElement()` the browser throws `NotSupportedError`); only `super()`, `attachShadow()`, `attachInternals()`, and building the internal structure of the shadow root are allowed.
- **[MANDATORY]** `connectedCallback` performs setup (global listeners, observers, fetches, timers) and `disconnectedCallback` the symmetric cleanup: create an `AbortController` on connection, pass `{ signal }` to every `addEventListener`, and call `abort()` on disconnection; `connectedCallback` runs again on every move within the DOM, so setup must be idempotent.
- **[PATTERN]** Shadow DOM with `this.attachShadow({ mode: 'open' })` and styles via a constructable `CSSStyleSheet` created once at module level with `sheet.replaceSync(css)` and assigned with `shadowRoot.adoptedStyleSheets = [sheet]` (Chrome 73+, Firefox 101+, Safari 16.4+): a single parse for all instances.
- **[PATTERN]** Attributes for declarative configuration (strings, booleans by presence), properties for the programmatic API and complex data; primitive properties reflect to the attribute (`set disabled(v) { this.toggleAttribute('disabled', Boolean(v)); }`); a boolean attribute is true if present, never `disabled="false"`.
- **[MANDATORY]** Observe attributes with the static field `static observedAttributes = ['value', 'max']` and handle them in `attributeChangedCallback(name, oldValue, newValue)` with an early return if `oldValue === newValue`; the update touches only the affected nodes, never a full re-render of the shadow root.
- **[PATTERN]** Properties set on the instance before the upgrade (component defined with `import()` after parsing): in `connectedCallback` check `Object.hasOwn(this, 'value')`, save the value, delete the own property, and reassign it, so it goes through the class setter.
- **[PATTERN]** Public events as `new CustomEvent('acme-change', { detail: { value }, bubbles: true, composed: true })` dispatched on the host: `composed: true` lets the event cross shadow boundaries when the component is nested in another component's shadow root; prefixed kebab-case names so they do not collide with native events (`change`, `toggle`, `select`); serializable `detail`.
- **[PATTERN]** Consumer content projected with `<slot>` and named slots (`<slot name="header">`); react to changes with the `slotchange` event by reading `slot.assignedElements({ flatten: true })`; style projected content with `::slotted()` and allow external customization via CSS custom properties (`var(--acme-accent, #0a66c2)`) and `::part()`.
- **[MANDATORY]** Custom form controls as form-associated custom elements: `static formAssociated = true`, `this.#internals = this.attachInternals()`, `internals.setFormValue(value)`, `internals.setValidity(flags, message, anchor)`, and the callbacks `formResetCallback`, `formDisabledCallback`, `formStateRestoreCallback` (Chrome 77+, Firefox 98+, Safari 16.4+); helper `<input type="hidden">` elements in the light DOM are forbidden.
- **[MANDATORY]** Accessibility: role and states via `ElementInternals` (`internals.role = 'switch'`, `internals.ariaChecked = 'true'`, supported in recent evergreen browsers) or explicit ARIA attributes; native internal controls (`<button type="button">`) or `tabindex="0"` with Enter and Space handling; `attachShadow({ mode: 'open', delegatesFocus: true })` when focus must reach the internal control; `:focus-visible` always styled.
- **[SECURITY]** No `innerHTML` with attribute or property values during rendering: the shadow root structure is static (created with `createElement()` or cloned from a constant `<template>`) and dynamic values go through `textContent` or `setAttribute()`; Shadow DOM isolates styles but is not a security boundary, not even with `mode: 'closed'`.
- **[PERFORMANCE]** Batch multiple attribute or property changes in the same task into a single update with `queueMicrotask()` and an `#updateScheduled` flag, or with `requestAnimationFrame` for purely visual updates.
- **[PERFORMANCE]** Define heavy components only when needed: `import('./acme-chart.js')` on visibility or interaction and `await customElements.whenDefined('acme-chart')`; hide not-yet-defined elements with `acme-chart:not(:defined) { visibility: hidden; }` to avoid a flash of unstyled content.
- **[TESTING]** Test components through their public API (attributes, properties, events, accessible roles) in happy-dom or jsdom, querying the shadow root with @testing-library/dom's `within(el.shadowRoot)`; for `ElementInternals`, form validation, and real layout use Vitest Browser Mode with Playwright, because simulated environments support them only partially.
- **[CONFIGURATION]** Document the public API with the JSDoc tags `@attr`, `@fires`, `@slot`, `@csspart`, and `@cssprop` on the class and generate `custom-elements.json` with `@custom-elements-manifest/analyzer` for IDEs and documentation.
- **[REFERENCE]** See `EXAMPLES.md` in this folder for reference anti-patterns and best practices.
