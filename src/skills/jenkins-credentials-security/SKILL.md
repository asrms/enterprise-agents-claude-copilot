# Skill: Jenkins Credentials & Security

## Implementation Rules:
- **[MANDATORY]** Use credentials only through Credentials Binding: `withCredentials([usernamePassword(credentialsId: 'harbor-payments-push', usernameVariable: 'REG_USR', passwordVariable: 'REG_PSW')])` and the `string`, `file`, `sshUserPrivateKey` bindings, or `environment { NEXUS = credentials('nexus-payments-deploy') }`, which for username/password also generates `NEXUS_USR` and `NEXUS_PSW`; the binding wraps the smallest possible block.
- **[FORBIDDEN]** Groovy interpolation of secrets such as `sh "curl -u ${REG_USR}:${REG_PSW} https://harbor.acme.internal/api/v2.0/projects"`: the value ends up in the recorded script and on the command line; always use single quotes, `sh 'curl -u "$REG_USR:$REG_PSW" https://harbor.acme.internal/api/v2.0/projects'`, and treat the "insecure interpolation of sensitive variables" warning as a blocking error in review.
- **[FORBIDDEN]** `echo`, `println`, `sh 'env'`, `printenv`, or debug output containing secrets; masking covers only the exact value, not its transformations (base64, URL-encoding, substrings, JSON): perform transformations in an `sh` preceded by `set +x`, because the `sh` step runs with tracing enabled (`-x`).
- **[SECURITY]** Pass secrets to tools via stdin, environment variables, or temporary files, never as arguments visible in the process list: `helm registry login --password-stdin`, `FLYWAY_PASSWORD="$DB_PSW"`, `file(credentialsId: 'harbor-push-dockerconfig', variable: 'DOCKER_AUTH')` copied into a temporary `DOCKER_CONFIG` removed with `trap`.
- **[FORBIDDEN]** Secrets in `parameters` (including `password` parameters), in plain-text `environment`, in the Jenkinsfile, in the library's `resources/`, in versioned Helm `values.yaml`, in archived artifacts, or assigned to `env.X` outside `withCredentials`, where they are no longer masked.
- **[ARCHITECTURE]** Credentials in the team folder's store (Folders plugin), not at the global level; `SYSTEM` scope only for credentials used by the controller itself (clouds, integrations), `GLOBAL` only for those shared by several teams; IDs follow the `<system>-<team>-<purpose>` convention (e.g. `harbor-payments-push`, `payments-staging-db-migration`).
- **[SECURITY]** Production credentials must not be reachable from PR builds: keep them in a separate release folder or job, because a `when { branch 'main' }` does not prevent a Jenkinsfile modified in a PR from reading its own folder's credentials.
- **[SECURITY]** Least privilege: tokens with the minimum permissions for their purpose (push only to the team's registry project, analysis-only SonarQube tokens, ServiceAccount limited to the target namespace), distinct credentials per environment, and periodic rotation of tokens and passwords (≤ 90 days).
- **[MANDATORY]** Controller with `numExecutors: 0` in JCasC: no builds on the built-in node, all work on ephemeral Kubernetes agents, so a pipeline cannot read `JENKINS_HOME`, `secrets/`, or `credentials.xml`.
- **[SECURITY]** Script Security: Jenkinsfiles and folder libraries always in the sandbox; in In-process Script Approval never approve dangerous signatures such as `staticMethod jenkins.model.Jenkins getInstance`, `staticMethod org.codehaus.groovy.runtime.DefaultGroovyMethods execute java.lang.String`, `new java.io.File java.lang.String`, or `method org.jenkinsci.plugins.workflow.support.steps.build.RunWrapper getRawBuild`; the Permissive Script Security plugin is forbidden.
- **[FORBIDDEN]** Reading credentials with `Jenkins.instance`, `CredentialsProvider.lookupCredentials`, or `hudson.util.Secret.decrypt` in pipeline code: they bypass binding, masking, folder permissions, and auditing.
- **[SECURITY]** Authorization with Role-based Authorization Strategy (or Matrix Authorization) managed in JCasC: no permissions for `anonymous`, `Overall/Administer` only for the admin group, item roles with a per-folder `pattern` (`payments/.*`), teams get `Job/Build`, `Job/Read`, `Job/Cancel`, `Credentials/View` but not `Credentials/Create` or `Credentials/Update`; authentication via LDAP/SAML/OIDC with groups.
- **[CONFIGURATION]** Controller configuration entirely in JCasC (versioned `jenkins.yaml`, loaded via `CASC_JENKINS_CONFIG`); secrets are referenced as `${HARBOR_PUSH_PASSWORD}` and resolved from environment variables, files in `/run/secrets`, or mounted Kubernetes Secrets, never written in plain text in the YAML.
- **[CONFIGURATION]** Hardening in JCasC: standard `crumbIssuer` enabled, `markupFormatter: plainText`, `disableRememberMe: true`, `slaveAgentPort: -1` if agents use WebSocket, `security.scriptApproval` with empty `approvedSignatures` and forced sandbox; plugins pinned in `plugins.txt` and updated on a defined cadence.
- **[SECURITY]** Multibranch with PRs from forks: trust "From users with Admin or Write permission" (`ForkPullRequestDiscoveryTrait` with `TrustPermission`), so for untrusted forks the target branch's Jenkinsfile is used instead of the modified one.
- **[PATTERN]** For Git pushes from the pipeline use `gitUsernamePassword(credentialsId: 'gitops-bot', gitToolName: 'Default')` or `sshagent(['gitops-bot-ssh'])`, preferably with short-lived GitHub App credentials; never URLs with an embedded token such as `https://jenkins:TOKEN@git.acme.internal/platform/gitops-payments.git`.
- **[PATTERN]** When available, integrate an external secret manager (HashiCorp Vault plugin with `withVault`, Kubernetes Credentials Provider) to avoid copies of secrets in the controller's store and to centralize rotation and auditing.
- **[TESTING]** In the Jenkinsfile and library CI: a blocking check that rejects `sh "` containing `_PSW`, `TOKEN`, `PASSWORD` variables, JenkinsPipelineUnit tests that verify a literal `$VAR` in recorded `sh` scripts, and a repository secret scan (gitleaks or `trivy fs --scanners secret`).
- **[TESTING]** Periodic auditing: Audit Trail plugin enabled, quarterly review of unused credentials, roles, and approved signatures, anonymous access test (`curl -s -o /dev/null -w '%{http_code}' "$JENKINS_URL/api/json"` must return 403).
- **[REFERENCE]** See `EXAMPLES.md` in this folder for reference anti-patterns and best practices.
