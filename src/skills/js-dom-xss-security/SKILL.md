# Skill: DOM Security and XSS Prevention

## Implementation Rules:
- **[MANDATORY]** Treat as untrusted user input, API responses, `location.hash`, `location.search`, `document.referrer`, `window.name`, `postMessage` messages, and data read from storage: they are DOM XSS sources just like a form field.
- **[MANDATORY]** Insert text only with `textContent`, `document.createTextNode()`, `element.append('string')`, or typed properties (`input.value`, `el.dataset.x`); `innerHTML`, `outerHTML`, `insertAdjacentHTML()`, `document.write()`, and `Range.createContextualFragment()` with untrusted data are forbidden.
- **[MANDATORY]** Untrusted rich HTML (comments, rendered markdown, CMS content) sanitized with DOMPurify and an explicit allowlist: `DOMPurify.sanitize(dirty, { ALLOWED_TAGS: ['p', 'strong', 'em', 'a'], ALLOWED_ATTR: ['href'] })`, adding `RETURN_TRUSTED_TYPE: true` when Trusted Types are active; DOMPurify must be kept up to date because bypasses are fixed frequently.
- **[PATTERN]** Native Sanitizer API (`element.setHTML(dirty)`): partial and recent support, not available in all browsers; use it only behind the feature detection `'setHTML' in Element.prototype` with a fallback to DOMPurify.
- **[SECURITY]** Enable Trusted Types with the CSP `require-trusted-types-for 'script'; trusted-types app-html dompurify` and create named policies with `trustedTypes.createPolicy('app-html', { createHTML: (s) => DOMPurify.sanitize(s) })`; support is complete in Chromium (83+) but not in all other browsers: feature-detect with `window.trustedTypes?.createPolicy` and apply sanitization everywhere anyway.
- **[SECURITY]** Strict CSP without `'unsafe-inline'` and `'unsafe-eval'` for scripts: `script-src 'nonce-{random}' 'strict-dynamic'; object-src 'none'; base-uri 'none'; frame-ancestors 'self'`, with a random nonce generated by the server on every response.
- **[FORBIDDEN]** `eval()`, `new Function()`, `setTimeout('code')`/`setInterval('code')` with strings, `script.textContent = data`, dynamically generated inline handlers (`onclick="deleteItem(42)"`), and `javascript:` URLs; enable the ESLint rules `no-eval`, `no-implied-eval`, `no-new-func`, and `no-script-url` at `error` level.
- **[MANDATORY]** Validate every dynamic URL before assigning it to `href`, `src`, `action`, `formAction`, `location`, or `window.open()`: parse with `new URL(raw, location.origin)` (preceded by `URL.canParse()`: Chrome 120+, Firefox 115+, Safari 17+) and an allowlist `new Set(['https:', 'http:', 'mailto:'])` on `url.protocol`; regexes and `startsWith('javascript:')` are forbidden, as they can be bypassed with uppercase letters, spaces, or leading tabs.
- **[SECURITY]** Post-login redirects and `returnUrl` parameters are accepted only if `new URL(raw, location.origin).origin === location.origin`, to prevent open redirects to phishing domains.
- **[MANDATORY]** `postMessage` always with an explicit `targetOrigin` (`frame.contentWindow.postMessage(data, 'https://pay.example.com')`), never `'*'`; on receipt compare `event.origin` with `===` against an allowlist (never `includes()`, `startsWith()`, or `endsWith()`), verify `event.source`, and validate the shape and types of `event.data` before using it.
- **[SECURITY]** Links to external origins with `target="_blank"` always accompanied by `rel="noopener noreferrer"`; programmatic opening with `window.open(url, '_blank', 'noopener,noreferrer')`.
- **[FORBIDDEN]** Session tokens, JWTs, and refresh tokens in `localStorage`, `sessionStorage`, or IndexedDB, readable by any injected script: use `HttpOnly; Secure; SameSite=Lax` cookies set by the server (BFF pattern); if an access token must live in the client, only in memory and short-lived.
- **[SECURITY]** Defense against prototype pollution: when merging or assigning dynamic keys from untrusted JSON, discard `__proto__`, `constructor`, and `prototype`; use `Map` or `Object.create(null)` for dictionaries with arbitrary keys, `Object.hasOwn()` for lookups, and an allowlist of keys and values for configurations.
- **[SECURITY]** Scripts and stylesheets from CDNs with Subresource Integrity and a pinned version: an `integrity` attribute with a base64 `sha384` hash and `crossorigin="anonymous"`, hash generated with `openssl dgst -sha384 -binary purify.min.js | openssl base64 -A`; never URLs with `@latest` or floating versions.
- **[PATTERN]** Dynamic attributes set with `setAttribute()` only for allowlisted names: never `on*`, `style`, `srcdoc`, or `formaction` attributes, nor `href`/`src` without URL validation.
- **[FORBIDDEN]** Home-made mini template engines that concatenate HTML strings, `element.innerHTML = marked.parse(markdown)` without sanitization, jQuery `$(userInput)` or `$(el).html(data)`.
- **[TESTING]** Regression tests with real payloads: `<img src=x onerror=alert(1)>`, `<svg onload=alert(1)>`, `javascript:alert(1)`, `JaVaScRiPt:alert(1)`, `{"__proto__":{"isAdmin":true}}`; assert that no generated `img` or `svg` nodes exist, that `href` is not set, and that `({}).isAdmin` remains `undefined`.
- **[CONFIGURATION]** Introduce the CSP first as `Content-Security-Policy-Report-Only` with a `report-to` directive to discover existing sinks, then switch to enforcement; in development with Vite set the headers via `server.headers` in `vite.config.js`.
- **[REFERENCE]** See `EXAMPLES.md` in this folder for reference anti-patterns and best practices.
