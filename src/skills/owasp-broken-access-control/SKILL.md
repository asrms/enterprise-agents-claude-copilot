# Skill: Broken Access Control (OWASP A01:2021)

## Implementation Rules:
- **[ARCHITECTURE]** Deny by default: every endpoint requires authentication and explicit authorization; Spring Security with `anyRequest().denyAll()` (or `.authenticated()`) as the last rule, FastAPI with `APIRouter(dependencies=[Depends(get_principal)])`, NestJS with a global `APP_GUARD`, Express with authentication middleware mounted before all routes; public exceptions are an allowlist of exact paths with `permitAll()`.
- **[ARCHITECTURE]** Authorization centralized in a policy layer (Spring `@PreAuthorize` with an `@authz` bean or `PermissionEvaluator`, a Python policy service, CASL/Casbin/OPA in Node) instead of `if`s scattered across controllers; every decision is testable in isolation.
- **[MANDATORY]** Object-level authorization (BOLA/IDOR, CWE-639) on every request that receives an ID: the query includes owner or tenant (`findByIdAndOwnerId(id, principalId)`, `WHERE id = :id AND tenant_id = :tid`) for GET, PUT, PATCH, DELETE, download, export, and bulk; for nested resources (`/orders/{orderId}/items/{itemId}`) verify that the item belongs to the order and the order to the principal.
- **[PATTERN]** For objects not owned by the caller return 404 (not 403) when the very existence of the resource is sensitive information, with message and timing identical to the "does not exist" case.
- **[FORBIDDEN]** Authorization decisions based on client-controlled data: `role`, `isAdmin`, `userId`, `ownerId`, `tenantId` in the body or query, custom headers (`X-User-Id`, `X-Tenant-Id`, `X-Role`), hidden fields, unsigned cookies, unverified JWT claims; identity, roles, and tenant derive only from the server-side session or from a token with a verified signature.
- **[MANDATORY]** Mass assignment (CWE-915): explicit input DTOs per operation (e.g. `UpdateProfileRequest` without `role`, `enabled`, `balance`, `tenantId`), Pydantic `model_config = ConfigDict(extra="forbid")`, zod `.strict()`, `spring.jackson.deserialization.fail-on-unknown-properties=true` on DTOs; never bind JPA `@Entity`s, Mongoose documents, or ORM models directly from the request.
- **[FORBIDDEN]** `Object.assign(entity, req.body)`, `prisma.<model>.update({ data: req.body })`, `Model.update(req.body)`, `BeanUtils.copyProperties(request, entity)`, `setattr` in a loop over `payload.dict()`/`model_dump()`, `@ModelAttribute` on persistent entities.
- **[MANDATORY]** Excessive property exposure (read-side BOPLA, OWASP API3:2023): output DTOs with a field allowlist (Pydantic `response_model`, dedicated Java records, Prisma `select`); never serialize entities with `passwordHash`, `mfaSecret`, `resetTokenHash`, internal flags, or other tenants' data.
- **[MANDATORY]** Function-level authorization (CWE-862/CWE-285): administrative endpoints and privileged operations protected on the server with a role or permission check (`@PreAuthorize("hasRole('ADMIN')")`, `Depends(require_role("admin"))`, `@Roles('admin')` + `RolesGuard`, `requireRole('ADMIN')`); hiding a button in the UI is not a control.
- **[MANDATORY]** Multi-tenant isolation: `tenant_id` extracted only from the verified token or the session and applied to every query (Hibernate 6 `@TenantId` or `@Filter`, PostgreSQL Row-Level Security with `SET app.tenant_id`, Prisma/Mongoose middleware), to every cache key, and to the prefix of storage objects; async jobs and queue consumers propagate the tenant of the verified message.
- **[SECURITY]** CORS (CWE-942): an exact allowlist of origins (`setAllowedOrigins(List.of("https://app.example.com"))`); forbidden: `Access-Control-Allow-Origin: *` or reflecting the `Origin` header together with `Access-Control-Allow-Credentials: true`, `addAllowedOriginPattern("*")` with `setAllowCredentials(true)`, unanchored regexes (`example\.com` accepts `evilexample.com`), and the `null` origin.
- **[REVIEW]** Bypass via path and method: in Spring Security 6 use `requestMatchers` (`antMatchers`/`mvcMatchers` were removed) and verify that the rules cover all verbs — a rule on `HttpMethod.POST` leaves PUT/PATCH/DELETE open; in Express mount `app.use('/api/admin', requireAuth, requireRole('ADMIN'))` before the routes; disable method override (`X-HTTP-Method-Override`, `_method`) or subject it to the same rules.
- **[REVIEW]** Grep: `findById\(|findOne\(|get_or_404|findByPk\(|findUnique\(` and verify that the result is filtered by owner/tenant; `permitAll\(\)|@PermitAll|web\.ignoring\(\)`; `req\.(body|query|headers)\[?['.]?(role|isAdmin|userId|tenantId|x-user-id|x-tenant-id)`; `data:\s*req\.body`, `Object\.assign\(`, `BeanUtils\.copyProperties\(`.
- **[SECURITY]** Non-enumerable IDs (UUIDv4/v7) reduce discovery but do not replace the ownership check: an IDOR on UUIDs is still a finding; in CVSS consider AC:H only if the IDs cannot be obtained from other APIs, logs, emails, or shared links.
- **[PATTERN]** Authorize state transitions too (CWE-841): approve only `PENDING` orders, prevent self-approval of one's own requests (segregation of duties), revalidate permissions at every step of a multi-request workflow.
- **[FORBIDDEN]** Checks only in the frontend, only in the API gateway by base path without re-checking objects in the service, or on an object different from the one being modified (check on the path `{id}` and update on the body `id`: TOCTOU/confused deputy).
- **[SECURITY]** Files and object storage: private buckets, pre-signed URLs with expiry ≤ 15 minutes generated only after the ownership check, unpredictable object keys prefixed by the tenant.
- **[CONFIGURATION]** Spring: `@EnableMethodSecurity` is mandatory when using `@PreAuthorize` (without it the annotations are silently ignored); FastAPI: security dependencies at the router level, not only on individual endpoints; Express/NestJS: middleware and guard order verified for every mounted router.
- **[PERFORMANCE]** Filter by owner/tenant in the query with a composite index `(tenant_id, id)` instead of loading and filtering in memory: it avoids full scans and prevents leaks through `count` and pagination.
- **[TESTING]** Test matrix for every endpoint: anonymous → 401, user without the role → 403, user of another owner/tenant → 404, owner → 200; negative mass assignment test (`"role": "ADMIN"` in the body → 400 or field ignored and verified in the DB); tools: MockMvc with `@WithMockUser`, pytest `TestClient` with two users, supertest.
- **[CWE]** CWE-639, CWE-862, CWE-863, CWE-285, CWE-425, CWE-352, CWE-22, CWE-601 → A01:2021; CWE-915 is officially mapped to A08:2021 (also cite API3:2023 BOPLA); CWE-942 (permissive CORS) is mapped to A05:2021.
