# Skill: Jenkins Pipeline Performance

## Implementation Rules:
- **[ARCHITECTURE]** The controller orchestrates and the agents do the work: file processing, parsing, compression, HTTP calls, and loops happen in `sh` on the agents; CPS Groovy code runs on the controller, is serialized at every step, and a heavy Jenkinsfile slows down every build on the instance.
- **[PATTERN]** Independent checks in `parallel` with `failFast true` on the parent stage or `options { parallelsAlwaysFailFast() }` at the pipeline level; every branch has a unique name and its own `agent`, because a stage with `parallel` cannot declare `agent`.
- **[PATTERN]** Version or platform combinations with `matrix` (`axes`, `excludes`) instead of copied stages; the agent can use the axis value (`yamlFile "ci/pod-node${NODE_VERSION}.yaml"`) and cells run in parallel.
- **[FORBIDDEN]** Fan-out of dozens of dynamically generated `parallel` branches beyond `containerCapStr` or the namespace `ResourceQuota`: every branch is a pod plus CPS overhead; limit parallelism or split tests into a few shards with Parallel Test Executor (`splitTests(parallelism: count(4), generateInclusions: true)`).
- **[PERFORMANCE]** `stash`/`unstash` only for small artifacts (under ~10 MB: charts, digests, metadata, reports), because they pass through and are stored on the controller; for large binaries use the same pod with nested stages, the repository manager (Nexus/Artifactory), or Artifact Manager on S3.
- **[PERFORMANCE]** Persistent dependency caches: local Maven repository on a PVC (`-Dmaven.repo.local=/home/jenkins/.m2/repository`) with a Nexus proxy in `settings.xml`, npm cache (`npm ci --cache /cache/npm --prefer-offline --no-audit --no-fund`), `GRADLE_USER_HOME` on a volume with `--build-cache`, layer cache with `--import-cache`/`--export-cache type=registry`.
- **[PERFORMANCE]** Targeted checkout: shallow clone with `CloneOption` (`shallow: true, depth: 1, noTags: true, honorRefspec: true`) configured as a Multibranch trait or with an explicit `checkout` after `skipDefaultCheckout()`; stages that do not use sources (approvals, quality gates, notifications) do not check out.
- **[FORBIDDEN]** Shallow clones in stages that need Git history (SonarQube analysis with blame and new code, version computed with `git describe`, changelog generation): there use a sufficient `depth` or `git fetch --unshallow`; the SonarQube message "Shallow clone detected" indicates loss of blame information.
- **[PERFORMANCE]** `options { durabilityHint('PERFORMANCE_OPTIMIZED') }` in branch and PR CI pipelines to reduce controller I/O; keep the default `MAX_SURVIVABILITY` in release pipelines with `input` and deploys, because after an unclean controller restart an optimized pipeline cannot resume.
- **[FORBIDDEN]** `readFile` plus Groovy loops over large files, `JsonSlurper`/`XmlSlurper` on bulky reports, `findFiles(glob: '**/*')` over the entire workspace, `sh(returnStdout: true)` with MBs of output: they load the controller's memory and CPU; filter with `jq`, `yq`, `awk` in the shell and return only the result.
- **[PERFORMANCE]** Aggregate commands: one `sh` call with a multi-line script instead of dozens of one-line `sh` calls (every step is a controller-agent round trip and a CPS checkpoint); long scripts in versioned files (`ci/scripts/*.sh`) or in the library's `resources/`.
- **[PATTERN]** Use the summaries returned by steps instead of re-processing reports: `def tests = junit(testResults: '**/target/surefire-reports/*.xml')` exposes `totalCount` and `failCount`; no manual parsing of Surefire XML files.
- **[PATTERN]** No wasted work: `disableConcurrentBuilds(abortPrevious: true)` cancels superseded builds of the same branch or PR, `milestone` in release pipelines aborts obsolete builds, `beforeAgent true` in `when` avoids pods for skipped stages.
- **[PERFORMANCE]** In monorepos build only what changes: `when { beforeAgent true; anyOf { branch 'main'; changeset 'services/payments/**' } }`, Maven `-pl payments-core -am` and `-T 1C` for parallel multi-module builds, targeted Gradle tasks.
- **[PERFORMANCE]** Pods ready quickly: lean tool images served from the internal registry, `imagePullPolicy: IfNotPresent` with immutable tags, pre-pull of the most used images on build nodes, and realistic requests so the scheduler does not leave pods `Pending`.
- **[CONFIGURATION]** Explicit limits: `timeout` at pipeline and stage level, `activeDeadlineSeconds` on the pod, `buildDiscarder(logRotator(numToKeepStr: '30', artifactNumToKeepStr: '5'))` to contain disk usage and job load times on the controller.
- **[TESTING]** Measure before optimizing: per-stage duration from Pipeline Graph View or Stage View, metrics exported with the Prometheus Metrics plugin (`/prometheus/` endpoint), or per-stage and per-step traces with the OpenTelemetry plugin; compare the median of at least 10 builds before and after every change.
- **[TESTING]** Define duration budgets (e.g. PRs under 10 minutes, release up to staging under 25 minutes) with alerts when the median exceeds the threshold; queue wait time and pod provisioning time are part of the budget.
