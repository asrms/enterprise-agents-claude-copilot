# Skill: Externalized Configuration and Observability in Spring Boot

## Implementation Rules:
- **[MANDATORY]** Group application configuration in `record`s annotated with `@ConfigurationProperties(prefix = "billing.invoice")` and `@Validated`, with Bean Validation constraints on the components (`@NotNull Duration paymentTerm`, `@Min(1) int maxRetries`, `@NotBlank String senderAddress`), and register them with `@ConfigurationPropertiesScan` or `@EnableConfigurationProperties`.
- **[FORBIDDEN]** Do not scatter `@Value("${billing.invoice.sender}")` and the like across services: it is allowed only for single values in `@Configuration` classes; never `@Value` with defaults that hide missing configuration (`@Value("${partner.url:http://localhost}")`) or `Environment#getProperty` in business code.
- **[PATTERN]** Use strong types in properties (`Duration` with values `30s`/`PT30S`, `DataSize` with `10MB`, `URI`, `enum`, `List<String>`) and `@DefaultValue` only for safe defaults; add `spring-boot-configuration-processor` as an `annotationProcessor` to generate metadata and autocompletion.
- **[CONFIGURATION]** Keep an `application.yml` with common safe defaults and `application-{profile}.yml` files only for real environment differences; activate profiles externally (`SPRING_PROFILES_ACTIVE`) and use `spring.profiles.group.*` to compose them; using `@Profile` to vary business logic is forbidden.
- **[SECURITY]** Externalize all secrets: environment variables (`${DB_PASSWORD}`), Kubernetes secrets mounted with `spring.config.import=optional:configtree:/run/secrets/`, or Spring Cloud Vault (`spring.config.import=vault://`); no secrets in versioned YAML, Docker images, or logs, and the `toString()` of configuration records masks sensitive values.
- **[MANDATORY]** Always set `spring.application.name`: it is used by tracing, metrics (`management.metrics.tags.application=${spring.application.name}`), and structured logs to identify the service.
- **[SECURITY]** Expose the bare minimum of Actuator: `management.endpoints.web.exposure.include=health,info,prometheus`, `management.endpoint.health.show-details=when-authorized`, a separate `management.server.port`, and never `exposure.include=*` outside local development.
- **[CONFIGURATION]** Enable probes with `management.endpoint.health.probes.enabled=true` and define the health groups: `management.endpoint.health.group.liveness.include=livenessState` (never external dependencies in liveness) and `management.endpoint.health.group.readiness.include=readinessState,db` (plus essential brokers or services), mapped to `/actuator/health/liveness` and `/actuator/health/readiness`.
- **[PATTERN]** Record business metrics with `MeterRegistry` (`Counter.builder("orders.placed").tag("channel", channel).register(registry)`) or with the Observation API (`@Observed(name = "invoice.generation")` with an `ObservedAspect` bean), using dot-notation names and units in the base name (`.duration`, `.size`).
- **[FORBIDDEN]** Do not use high-cardinality values as metric tags (`customerId`, `orderId`, URLs with non-normalized path variables, emails): they explode the time series in Prometheus; use them as span attributes or log fields.
- **[PERFORMANCE]** Enable histograms and SLOs only on useful metrics: `management.metrics.distribution.percentiles-histogram.http.server.requests=true` and `management.metrics.distribution.slo.http.server.requests=100ms,300ms,1s`, exporting via `micrometer-registry-prometheus`.
- **[CONFIGURATION]** Enable distributed tracing with `micrometer-tracing-bridge-otel` + `opentelemetry-exporter-otlp`, `management.otlp.tracing.endpoint=http://otel-collector:4318/v1/traces`, and an explicit `management.tracing.sampling.probability` (e.g. `0.1` in production, `1.0` in tests); use the auto-configured `RestClient.Builder`/`WebClient.Builder` and `KafkaTemplate` to propagate `traceparent`.
- **[PATTERN]** Propagate a business correlation id as baggage: `management.tracing.baggage.remote-fields=x-correlation-id` and `management.tracing.baggage.correlation.fields=x-correlation-id` to have it in MDC and in outgoing headers; if missing, generate it in a `OncePerRequestFilter` and return it in the response header.
- **[CONFIGURATION]** With Spring Boot 3.4+ use native structured logging: `logging.structured.format.console=ecs` (or `logstash`/`gelf`) in production, text format only locally; `traceId` and `spanId` are included automatically in MDC by Micrometer Tracing (`logging.pattern.correlation` for the text format, Boot 3.2+).
- **[FORBIDDEN]** Do not log personal data, tokens, passwords, or full payloads; use SLF4J parameterized logging (`log.info("Order {} confirmed", orderId)`), never concatenation, and do not use `DEBUG`/`TRACE` levels (e.g. `org.hibernate.SQL`) in production.
- **[CONFIGURATION]** Guarantee graceful shutdown with `server.shutdown=graceful` (the default since Spring Boot 3.4) and `spring.lifecycle.timeout-per-shutdown-phase=30s`, coordinated with Kubernetes' `terminationGracePeriodSeconds` (greater than the timeout) and a `preStop` of a few seconds to drain traffic.
- **[PATTERN]** Expose build information on `/actuator/info` with the `build-info` goal of `spring-boot-maven-plugin` and `git-commit-id-maven-plugin` (`management.info.git.mode=simple`), without including environment properties (`management.info.env.enabled=false`).
- **[TESTING]** Verify configuration with `ApplicationContextRunner` (property binding and validation, startup failure with missing values) and test `/actuator/health/readiness` and `/actuator/prometheus` in a `@SpringBootTest(webEnvironment = RANDOM_PORT)` with Testcontainers.
- **[REFERENCE]** See `EXAMPLES.md` in this folder for reference anti-patterns and best practices.
