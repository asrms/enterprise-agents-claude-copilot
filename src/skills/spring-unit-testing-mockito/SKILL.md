# Skill: Unit and Integration Testing with JUnit 5, Mockito, and Testcontainers

## Implementation Rules:
- **[ARCHITECTURE]** Follow the test pyramid: pure unit tests (no Spring context) for domain and use cases, test slices for adapters (`@WebMvcTest`, `@DataJpaTest`, `@JsonTest`), a few end-to-end `@SpringBootTest`s with Testcontainers; `@SpringBootTest` is forbidden for testing the logic of a single service.
- **[MANDATORY]** Annotate unit tests with `@ExtendWith(MockitoExtension.class)` keeping the default `STRICT_STUBS` strictness: unused stubs must fail the test with `UnnecessaryStubbingException`; `lenient()` and `@MockitoSettings(strictness = Strictness.LENIENT)` are allowed only with a justifying comment.
- **[PATTERN]** Create the class under test explicitly in `@BeforeEach` passing the mocks to the constructor (`sut = new PlaceOrderService(loadCustomerPort, saveOrderPort, clock)`), consistent with constructor injection in production code; avoid `@InjectMocks`, which fails silently if the constructor changes.
- **[PATTERN]** Structure every test in `// given`, `// when`, `// then` blocks with BDDMockito: `given(loadOrderPort.load(orderId)).willReturn(order)`, `then(saveOrderPort).should().save(captor.capture())`, `then(publisher).shouldHaveNoInteractions()`.
- **[MANDATORY]** Use AssertJ for all assertions (`assertThat(...)`, `assertThatThrownBy(() -> sut.confirm(id)).isInstanceOf(OrderNotFoundException.class).hasMessageContaining(...)`, `usingRecursiveComparison().ignoringFields("id")`, `extracting(...)`); do not mix `org.junit.jupiter.api.Assertions` and Hamcrest.
- **[PATTERN]** Verify the arguments of side effects with `@Captor ArgumentCaptor<Order>` and AssertJ assertions on the captured value, instead of complex `argThat` or generic `any()`; if one argument uses a matcher, all must use one (`eq(...)`).
- **[FORBIDDEN]** Do not mock value objects, records, DTOs, entities, or collections: instantiate them with real data or test data builders (`OrderFixtures.confirmedOrder()`); do not mock the class under test or use `spy` on it.
- **[FORBIDDEN]** Do not mock types you do not own (`RestClient`, `KafkaTemplate`, `EntityManager`, `JdbcTemplate`): hide them behind a port whose contract you own and test the real adapter with Testcontainers or WireMock.
- **[PATTERN]** Verify with `then(...).should()` only commands (side effects: save, publish, send); do not verify queries already stubbed with `given`, because it duplicates the stub and makes the test brittle.
- **[MANDATORY]** Make tests deterministic: inject a `Clock` (`Clock.fixed(Instant.parse("2025-01-15T10:00:00Z"), ZoneOffset.UTC)`) instead of `Instant.now()`, replaceable id generators, and no dependence on execution order or on data shared between tests.
- **[CONFIGURATION]** In test slices use `@MockitoBean` and `@MockitoSpyBean` (`org.springframework.test.context.bean.override.mockito`, Spring Framework 6.2 / Spring Boot 3.4+); `@MockBean` and `@SpyBean` are deprecated in Boot 3.4 and removed in Boot 4, where test slices move to dedicated modules (e.g. `spring-boot-webmvc-test`).
- **[PATTERN]** Test web adapters with `@WebMvcTest(OrderController.class)` and `MockMvc`/`MockMvcTester` (Spring Boot 3.4+), importing the real security configuration with `@Import(ApiSecurityConfig.class)` and using `SecurityMockMvcRequestPostProcessors.jwt()` for authentication.
- **[PATTERN]** Test the persistence adapter with `@DataJpaTest` + `@AutoConfigureTestDatabase(replace = AutoConfigureTestDatabase.Replace.NONE)` on a real PostgreSQL via Testcontainers (`@Container @ServiceConnection static PostgreSQLContainer<?> postgres = new PostgreSQLContainer<>("postgres:16-alpine")`, Spring Boot 3.1+); H2 is forbidden as a substitute for the production database.
- **[PERFORMANCE]** Reuse containers and contexts: declare containers `static` in a base class or in a shared `@TestConfiguration` with `@ServiceConnection` beans, avoid `@DirtiesContext` and differing `@MockitoBean` variants across classes to take advantage of the Spring context cache.
- **[FORBIDDEN]** Do not use `Thread.sleep` to wait for async effects: use Awaitility (`await().atMost(Duration.ofSeconds(10)).untilAsserted(() -> assertThat(repository.findById(id)).isPresent())`).
- **[PATTERN]** Name tests descriptively with the `should<Result>_when<Condition>` pattern (e.g. `shouldRejectOrder_whenStockIsInsufficient`) or with `@DisplayName` in domain language, grouping cases with `@Nested`; cover input variants with `@ParameterizedTest` + `@CsvSource`/`@MethodSource`.
- **[CONFIGURATION]** With Java 21 and Mockito 5 (inline mock maker by default) configure Mockito as a Java agent in Surefire/Gradle (`-javaagent:${org.mockito:mockito-core:jar}` with `maven-dependency-plugin:properties`) to avoid the dynamic agent loading warning and the JDK's future block.
- **[TESTING]** Set quality thresholds in CI with JaCoCo (`jacoco:check`, at least 80% line coverage on `domain` and `application`) and consider PIT mutation testing (`pitest-maven`) on critical domain modules.
- **[REFERENCE]** See `EXAMPLES.md` in this folder for reference anti-patterns and best practices.
