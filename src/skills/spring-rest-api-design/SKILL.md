# Skill: REST API Design with Spring MVC

## Implementation Rules:
- **[ARCHITECTURE]** Controllers are thin adapters: they validate input, map DTO → command, invoke a single use case (inbound port), and map the result → response; no business logic, no `@Transactional`, no repository access in controllers.
- **[MANDATORY]** Define requests and responses as dedicated Java `record`s per operation (`CreateOrderRequest`, `UpdateOrderAddressRequest`, `OrderResponse`); the creation request does not contain `id`, `status`, `createdAt`, or other server-managed fields (mass assignment prevention).
- **[FORBIDDEN]** Do not use JPA entities or domain objects as `@RequestBody` or as a controller's return type, nor `Map<String, Object>`/`JsonNode` as the contract of typed APIs.
- **[MANDATORY]** Validate the body with `@Valid @RequestBody` and Bean Validation constraints on the record components (`@NotBlank`, `@Size(max = 255)`, `@Positive`, `@Email`, `@NotNull @Valid List<@Valid OrderLineRequest>`); constrain path and query params (`@PathVariable @Positive long id`) relying on Spring Framework 6.1+'s native method validation or `@Validated` on the class.
- **[PATTERN]** Handle errors in a single `@RestControllerAdvice` that extends `ResponseEntityExceptionHandler` and returns `ProblemDetail` (RFC 9457, `Content-Type: application/problem+json`) with a stable `type` URI, `title`, `status`, `detail`, `instance`, and extended properties (`errors` per field, `traceId`); enable `spring.mvc.problemdetails.enabled=true`.
- **[PATTERN]** Map domain exceptions to semantic statuses: `OrderNotFoundException` → `404`, business invariant violation → `422`, state conflict or `ObjectOptimisticLockingFailureException` → `409`, unmet `If-Match` → `412`, `MethodArgumentNotValidException`/`HandlerMethodValidationException` → `400`; never `200` with an `error` field in the body.
- **[MANDATORY]** Use the correct success statuses: creation `POST` → `201 Created` with a `Location` header (`ServletUriComponentsBuilder.fromCurrentRequest().path("/{id}")`), `DELETE` → `204 No Content`, asynchronous processing → `202 Accepted` with the `Location` of the status resource, `GET` → `200`.
- **[PATTERN]** Name resources with plural kebab-case nouns (`/api/v1/purchase-orders/{orderId}/lines`) and model actions as sub-resources or state transitions (`POST /orders/{id}/cancellation`), never verbs in the path (`/getOrders`, `/cancelOrder`).
- **[PATTERN]** Paginate every collection: accept `Pageable` with `@PageableDefault(size = 20, sort = "createdAt")`, cap it with `spring.data.web.pageable.max-page-size=100`, and return a stable page DTO (`record PageResponse<T>(List<T> content, int page, int size, long totalElements)`) or `@EnableSpringDataWebSupport(pageSerializationMode = VIA_DTO)` (Spring Data 3.3+), never a directly serialized `PageImpl`.
- **[CONFIGURATION]** Version APIs in the path (`/api/v1`) or via media type and keep minor changes backward-compatible (only added, optional fields); with Spring Framework 7 / Spring Boot 4 consider native versioning (`@GetMapping(version = "1.1")` with `ApiVersionConfigurer`).
- **[MANDATORY]** Make `POST`s with economic or non-repeatable effects (payments, orders) idempotent via an `Idempotency-Key` header (UUID): store the key, payload hash, and response with a TTL (e.g. 24h), return the same response on replays, and `422`/`409` if the same key arrives with a different payload.
- **[PATTERN]** Support HTTP optimistic concurrency by exposing the `@Version` as an `ETag` (`ResponseEntity.ok().eTag("\"" + version + "\"")`) and requiring `If-Match` on `PUT`/`PATCH`; respond `428 Precondition Required` if the header is missing on protected resources.
- **[CONFIGURATION]** Serialize dates and times as ISO-8601 with offset (`Instant`, `OffsetDateTime`), amounts as `BigDecimal` with an explicit currency, enums as strings; set `spring.jackson.default-property-inclusion=non_null` and never expose internal sequential ids if non-enumerability is required (use UUIDs).
- **[SECURITY]** Limit input size (`@Size` on strings and lists, `spring.servlet.multipart.max-file-size`, `server.tomcat.max-swallow-size`) and never reflect technical exception messages, SQL, or stack traces in the `ProblemDetail`'s `detail`.
- **[CONFIGURATION]** Document APIs with springdoc-openapi (`org.springdoc:springdoc-openapi-starter-webmvc-ui` 2.x for Spring Boot 3, 3.x for Spring Boot 4) annotating `@Tag`, `@Operation`, and `@ApiResponse` with `ProblemDetail` schemas; disable the UI in production with `springdoc.swagger-ui.enabled=false`.
- **[PERFORMANCE]** Avoid chatty payloads and over-fetching: specific response DTOs for lists (summary) and detail, compression with `server.compression.enabled=true`, and explicit `Cache-Control` on cacheable resources (`CacheControl.maxAge(Duration.ofMinutes(5))`).
- **[TESTING]** Test every controller with `@WebMvcTest(OrderController.class)`, `@MockitoBean` on the use cases, and `MockMvc` or `MockMvcTester` (Spring Boot 3.4+), verifying status, `Location` header, JSON body, and `ProblemDetail` structure for validation and domain errors.
- **[TESTING]** Verify the generated OpenAPI contract (`/v3/api-docs`) in CI with a test that compares the schema with the approved version or with breaking-change detection tools (e.g. openapi-diff).
- **[REFERENCE]** See `EXAMPLES.md` in this folder for reference anti-patterns and best practices.
