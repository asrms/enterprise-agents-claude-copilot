# Skill: JPA and Hibernate 6 Performance with Spring Data

## Implementation Rules:
- **[MANDATORY]** Declare `fetch = FetchType.LAZY` explicitly on every `@ManyToOne` and `@OneToOne` (the JPA default is EAGER); `@OneToMany` and `@ManyToMany` remain LAZY. `FetchType.EAGER` is forbidden on any association.
- **[CONFIGURATION]** Set `spring.jpa.open-in-view=false` in every service: lazy loading outside the transaction must fail with `LazyInitializationException` during development, not trigger hidden queries during serialization.
- **[PATTERN]** Resolve N+1 by loading the associations the use case needs with `@EntityGraph(attributePaths = {"customer", "lines"})` on the repository method or with `JOIN FETCH` in JPQL; as a global safety net, set `spring.jpa.properties.hibernate.default_batch_fetch_size=50` (or `@BatchSize(size = 50)` on the collection).
- **[FORBIDDEN]** Do not combine `JOIN FETCH`/`@EntityGraph` on a collection with `Pageable`: Hibernate applies pagination in memory (warning `HHH90003004`). Paginate the ids first (`select o.id from OrderEntity o where o.customer.id = :customerId` with `Pageable`), then load the entities with `where o.id in :ids` and a fetch join; enable `spring.jpa.properties.hibernate.query.fail_on_pagination_over_collection_fetch=true`.
- **[FORBIDDEN]** Do not fetch-join two or more `List` collections at the same time (it causes `MultipleBagFetchException` or a Cartesian product): load one collection per query, or use `Set` with `default_batch_fetch_size`.
- **[PATTERN]** For list and report reads, use projections: `record` DTOs with a JPQL constructor expression (`select new com.acme.order.OrderSummary(o.id, o.status, c.name) from Order o join o.customer c`) or closed interface projections; do not hydrate managed entities just to display them.
- **[MANDATORY]** Annotate read-only use cases/services with `@Transactional(readOnly = true)`: Spring sets the Hibernate flush mode to `MANUAL` and marks the connection read-only, avoiding needless dirty checking and snapshots.
- **[PERFORMANCE]** For bulk inserts, use `@GeneratedValue(strategy = GenerationType.SEQUENCE)` with `@SequenceGenerator(name = "order_seq", sequenceName = "order_seq", allocationSize = 50)` aligned with the `INCREMENT BY` of the DB sequence; `GenerationType.IDENTITY` disables JDBC insert batching in Hibernate.
- **[CONFIGURATION]** Enable batching with `spring.jpa.properties.hibernate.jdbc.batch_size=50`, `spring.jpa.properties.hibernate.order_inserts=true`, `spring.jpa.properties.hibernate.order_updates=true`; for PostgreSQL, add `reWriteBatchedInserts=true` to the JDBC URL.
- **[PERFORMANCE]** In import jobs exceeding a few thousand rows, call `entityManager.flush()` and `entityManager.clear()` every `batch_size` items to prevent unbounded growth of the persistence context; for bulk updates, use `@Modifying(clearAutomatically = true, flushAutomatically = true)` with bulk JPQL queries.
- **[PERFORMANCE]** Prefer `Slice<T>` over `Page<T>` when the client does not need the total (it avoids the `count` query), and use keyset pagination with `Window<T>` and `ScrollPosition.keyset()` (Spring Data 3.1+) for deep datasets; always define a deterministic `Sort` that includes the id.
- **[CONFIGURATION]** Size HikariCP explicitly: `spring.datasource.hikari.maximum-pool-size` computed as `(core_count * 2) + effective_spindle_count` (typically 10-20, never hundreds), `connection-timeout=3000`, `max-lifetime` at least 30 s shorter than the DB/proxy-side timeout, and `leak-detection-threshold=20000` in non-production environments.
- **[MANDATORY]** Protect concurrently modified aggregates with `@Version private Long version;` and handle `ObjectOptimisticLockingFailureException` by translating it into `409 Conflict`; use `@Lock(LockModeType.PESSIMISTIC_WRITE)` only for documented, short, high-frequency contention.
- **[PATTERN]** Implement entity `equals`/`hashCode` on the immutable natural key, or on the id with `id != null && id.equals(other.getId())` and a constant `hashCode()` (`getClass().hashCode()`); never use Lombok `@Data` or `@EqualsAndHashCode` on entities, and never include collections in `toString()`.
- **[FORBIDDEN]** Do not return JPA entities from controllers, Kafka messages, or caches: they are proxies carrying session state; always map them to DTOs/records or to the domain model inside the transaction.
- **[FORBIDDEN]** Do not use `CascadeType.ALL` or `CascadeType.REMOVE` on `@ManyToOne`/`@ManyToMany`; use `cascade = CascadeType.ALL, orphanRemoval = true` only on parent → child compositions within the same aggregate, with `addLine()`/`removeLine()` helper methods that keep both sides in sync.
- **[PERFORMANCE]** Set `spring.jpa.properties.hibernate.query.in_clause_parameter_padding=true` to maximize plan cache reuse with variable `IN` clauses, and never concatenate parameters into queries (use named parameters such as `:customerId`).
- **[CONFIGURATION]** Manage the schema with Flyway or Liquibase and set `spring.jpa.hibernate.ddl-auto=validate` (never `update` or `create` outside tests); create explicit indexes on all foreign keys and on the columns used in `where`/`order by`.
- **[TESTING]** Verify the absence of N+1 in integration tests against a real database (Testcontainers) by counting statements with `hibernate.generate_statistics=true` and `Statistics#getPrepareStatementCount()` or with datasource-proxy, asserting a maximum number of queries per use case.
- **[PERFORMANCE]** Monitor slow queries in test environments with `spring.jpa.properties.hibernate.session.events.log.LOG_QUERIES_SLOWER_THAN_MS=200` and the `hikaricp.connections.pending`/`hikaricp.connections.acquire` metrics exposed by Micrometer.
- **[REFERENCE]** See `EXAMPLES.md` in this folder for reference anti-patterns and best practices.
