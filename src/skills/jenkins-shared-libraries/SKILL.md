# Skill: Jenkins Shared Libraries

## Implementation Rules:
- **[ARCHITECTURE]** A dedicated repository with the standard layout: `vars/` (one global var per `camelCase.groovy` file plus a `camelCase.txt` help file), `src/com/acme/ci/` (Groovy classes), `resources/com/acme/ci/` (pod templates, shell scripts, defaults), `test/` (unit tests); a Gradle build with the `groovy` plugin that compiles `src` and `vars` and runs the tests in CI.
- **[MANDATORY]** Consume the library with a version pinned to an immutable semver tag, `@Library('platform-lib@v2.3.1') _`; in production, floating branches (`@main`, `@develop`), unversioned libraries, and dynamic loading with `library identifier: 'platform-lib@main'` are forbidden; upgrades arrive via PRs (Renovate/Dependabot) on the Jenkinsfile.
- **[CONFIGURATION]** Register the library in JCasC (`unclassified.globalLibraries.libraries`) with `retriever.modernSCM`, `defaultVersion` on the latest tag, `implicit: false`, `allowVersionOverride: true` (required for pinning in the Jenkinsfile), and `includeInChangesets: false`, so library commits do not appear in the services' changelogs.
- **[MANDATORY]** Every global var exposes `def call(Map config = [:])` with named parameters: it merges the defaults (`Map cfg = DEFAULTS + config`), rejects unknown keys, checks types and required keys, and fails with `error "mavenBuild: parameter 'goals' is required"`; positional signatures such as `call(String, boolean, String)` are forbidden.
- **[PATTERN]** Standard pipelines as global vars (`vars/javaServicePipeline.groovy` containing a `pipeline { }` block) to standardize services: the application Jenkinsfile shrinks to `javaServicePipeline(serviceName: 'payments-api', jdk: '21')`; only one `pipeline` per build.
- **[PATTERN]** Classes in `src/` implement `Serializable` with `private static final long serialVersionUID = 1L`, receive the pipeline context (the global var's `this`) in the constructor, and invoke steps as `steps.sh('helm lint ./chart')`, `steps.withEnv(["NS=${namespace}"]) { }`, `steps.error('message')`.
- **[FORBIDDEN]** Non-serializable fields or local variables that outlive a step (`java.util.regex.Matcher`, `Iterator`, `JsonSlurper`'s `LazyMap`, connections, streams): they cause a `NotSerializableException` at the next CPS checkpoint; use `readJSON`/`readYaml` (Pipeline Utility Steps), which return serializable objects.
- **[FORBIDDEN]** `@NonCPS` on methods that invoke steps (`sh`, `echo`, `readFile`, `error`) or CPS closures: behavior becomes unpredictable; `@NonCPS` is allowed only for pure functions (regex, sorting, formatting) that receive and return simple types.
- **[FORBIDDEN]** `java.io.File`, `new URL(url).text`, `"kubectl get pods".execute()`, `Thread`, `HttpURLConnection` in the library: Groovy code runs on the controller and acts on its filesystem and network; use `readFile`, `writeFile`, `fileExists`, `findFiles`, and `sh` with `curl`, all executed on the agent.
- **[PATTERN]** Static templates and scripts in `resources/`, loaded with `libraryResource('com/acme/ci/scripts/helm-deploy.sh')` and written to the agent with `writeFile` before `sh`; no long heredocs or inline YAML built by concatenating Groovy strings.
- **[SECURITY]** Global libraries are trusted and run outside the sandbox: repository with branch protection, platform team CODEOWNERS, mandatory review, and protected tags; folder-level libraries run in the sandbox and must never require signature approvals.
- **[SECURITY]** No secrets in code or in `resources/`: the library receives only a `credentialsId` as a parameter, uses `withCredentials` and single-quoted `sh` internally, and passes non-secret values to the shell with `withEnv` rather than by interpolation.
- **[PATTERN]** A stable semver API: breaking changes only in a major, deprecations flagged with `echo "WARN: parameter 'jdkVersion' is deprecated, use 'jdk'"` for at least one minor, CHANGELOG updated on every tag.
- **[PERFORMANCE]** The library delegates heavy work to a single `sh` call on the agents: no CPS loops over hundreds of items, no `readFile` of multi-MB reports, no repeated `sh` for each module.
- **[PERFORMANCE]** Enable version caching on the controller (`cachingConfiguration` with `refreshTimeMinutes: 1440`) for tags, excluding floating branches with `excludedVersionsStr`, to avoid cloning the library on every build.
- **[CONFIGURATION]** Centralized defaults (registry, SonarQube installation name, coverage and CVSS thresholds) in `resources/com/acme/ci/defaults.yaml`, read with `readYaml(text: libraryResource('com/acme/ci/defaults.yaml'))` and overridable only through the documented parameters.
- **[TESTING]** Unit tests with JenkinsPipelineUnit (`com.lesfurets:jenkins-pipeline-unit`) on JUnit 5: extend `BasePipelineTest`, load the global var with `loadScript('vars/mavenBuild.groovy')` or register the library with `library().retriever(projectSource())`, mock steps with `helper.registerAllowedMethod`, and verify `helper.callStack`.
- **[TESTING]** Every global var has tests for missing or unknown parameters, for the error branch, and for the absence of secret interpolation (the recorded `sh` script contains a literal `$VAR`); the library's CI is green before the tag is created.
- **[TESTING]** Standard pipelines (`vars/*Pipeline.groovy`) are also verified with integration tests on an ephemeral Jenkins (Jenkinsfile Runner or `jenkins-test-harness`) before releasing a new major.
- **[REFERENCE]** See `EXAMPLES.md` in this folder for reference anti-patterns and best practices.
