# Skill: Security Hardening for the Next.js App Router

## Implementation Rules:
- **[SECURITY]** Every function exported from a `'use server'` file is a public HTTP POST endpoint, invocable with its action ID even if the component using it is not rendered: inside EVERY action perform, in this order, authentication (`await getSession()`), Zod validation of the input (`safeParse` on `FormData` or arguments), authorization on the resource (ownership, tenant, role), and only then the mutation.
- **[FORBIDDEN]** Trusting values sent by the client (`userId`, `role`, `price`, `tenantId`, `isAdmin` flags) or the fact that a button is hidden in the UI: identity is derived only from the server session, and prices and permissions are reloaded from the DB.
- **[ARCHITECTURE]** Centralize data access and checks in a Data Access Layer (`features/*/server/*` with `import 'server-only'`) that verifies session and permissions and returns minimal DTOs; pages, layouts, and actions do not query the DB directly.
- **[FORBIDDEN]** Using middleware/proxy as the only authorization check (cf. CVE-2025-29927, bypass via the `x-middleware-subrequest` header, fixed in Next 15.2.3): the proxy only performs optimistic redirects; the authoritative check lives in the DAL, actions, and Route Handlers.
- **[SECURITY]** `NEXT_PUBLIC_*` variables are inlined into the JavaScript bundle at build time: never secrets with that prefix (private API keys, DSNs, tokens, signing keys); secrets are read only from `lib/env.ts`, validated with Zod and protected by `import 'server-only'`.
- **[FORBIDDEN]** Passing secrets, tokens, hashes, or full records as props to Client Components: everything that crosses the boundary is serialized into the RSC payload, readable in the HTML source; as an additional defense consider `experimental.taint: true` with React's `experimental_taintUniqueValue`/`experimental_taintObjectReference` (experimental APIs).
- **[SECURITY]** Content Security Policy with a per-request nonce, generated in `middleware.ts` (Next 15, `middleware` function) or `proxy.ts` (Next 16, `proxy` function): `script-src 'self' 'nonce-<value>' 'strict-dynamic'`, `object-src 'none'`, `base-uri 'self'`, `form-action 'self'`, `frame-ancestors 'none'`; set the policy both in the request headers (Next.js applies the nonce to its own scripts) and in the response headers, and expose the nonce via `x-nonce`.
- **[CONFIGURATION]** A nonce-based CSP requires dynamic rendering (prerendered pages cannot have a per-request nonce): read the nonce with `(await headers()).get('x-nonce')` and pass it to third-party `<Script nonce={nonce}>`s; add `'unsafe-eval'` only if `process.env.NODE_ENV === 'development'`; `'unsafe-inline'` in `script-src` is forbidden.
- **[CONFIGURATION]** Global security headers in `next.config.ts` with `async headers()` on `source: '/:path*'`: `Strict-Transport-Security: max-age=63072000; includeSubDomains; preload`, `X-Content-Type-Options: nosniff`, `Referrer-Policy: strict-origin-when-cross-origin`, `X-Frame-Options: DENY`, `Permissions-Policy: camera=(), microphone=(), geolocation=()`; set `poweredByHeader: false`.
- **[FORBIDDEN]** `dangerouslySetInnerHTML` with unsanitized HTML (CMS, rendered markdown, user input): sanitize with DOMPurify (`isomorphic-dompurify` on the server) via `DOMPurify.sanitize(html, { USE_PROFILES: { html: true } })`, preferably in the Server Component before serializing the string.
- **[SECURITY]** Session cookies set only in Server Actions, Route Handlers, or middleware/proxy with `(await cookies()).set(name, value, { httpOnly: true, secure: true, sameSite: 'lax', path: '/', maxAge })` and the `__Host-` prefix; storing tokens in `localStorage`/`sessionStorage` or in cookies readable by JavaScript is forbidden.
- **[SECURITY]** Open redirect prevention: validate every `callbackUrl`/`next`/`returnTo` before `redirect()`, accepting only relative paths that start with `/` and not with `//` or `/\`, and verifying `new URL(value, origin).origin === origin`; alternatively use an allowlist of destinations.
- **[SECURITY]** Route Handlers (`app/**/route.ts`): export only the needed methods (the others automatically get 405), verify authentication and authorization in every handler, validate query and body with Zod, and respond with `Response.json(body, { status })` without stack traces; for webhooks verify the HMAC signature with `crypto.timingSafeEqual` on the raw body (`await request.text()`).
- **[SECURITY]** CSRF: Server Actions accept only POST and compare the `Origin` header with `Host`; behind a reverse proxy configure `experimental.serverActions.allowedOrigins` with only the known domains; cookie-authenticated POST/PUT/DELETE Route Handlers must verify `Origin` or an anti-CSRF token.
- **[CONFIGURATION]** Keep `experimental.serverActions.bodySizeLimit` at the default (1 MB) or at an explicit reduced value; for large uploads use a dedicated Route Handler or direct upload to storage with signed URLs.
- **[SECURITY]** Errors: in production Next.js replaces the message of server errors with a `digest`; actions must not return raw `error.message`s, stacks, or SQL details, but domain codes (`'FORBIDDEN'`, `'VALIDATION_ERROR'`), logging the details on the server.
- **[SECURITY]** Rate limiting per IP and per user on login, sign-up, password reset, email sending, and expensive actions (e.g. `@upstash/ratelimit` or a limiter at the gateway), with a 429 response and neutral messages that do not reveal whether an account exists.
- **[CONFIGURATION]** Supply chain: `npm audit --omit=dev` or Dependabot/Renovate in CI, committed lockfile with `npm ci` in the pipeline, and prompt updates of `next`, `react`, and `react-dom` to security patches (e.g. CVE-2025-29927 on middleware and CVE-2025-55182 on React Server Components, December 2025).
- **[TESTING]** Mandatory security tests for every action and Route Handler: rejection without a session, with invalid input, and on another user's or tenant's resource; Playwright tests that verify the presence of `content-security-policy` and `strict-transport-security` in the response and the absence of `x-powered-by`.
