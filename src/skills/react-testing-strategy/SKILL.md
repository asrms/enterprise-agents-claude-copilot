# Skill: React and Next.js Testing Strategy

## Implementation Rules:
- **[ARCHITECTURE]** Test pyramid: unit tests for pure functions, Zod schemas, reducers, and hooks; integration tests of Client Components with React Testing Library + MSW (the largest share); Playwright e2e tests for critical flows (login, checkout, main CRUD) and for all pages with async Server Components.
- **[MANDATORY]** RTL queries via `screen` in priority order: `getByRole` with `name` (`screen.getByRole('button', { name: /save/i })`), `getByLabelText`, `getByText`; `getByTestId` only when no role or accessible text exists.
- **[MANDATORY]** Interactions with `@testing-library/user-event` v14: `const user = userEvent.setup()` before `render` and `await user.click()`, `await user.type()`, `await user.keyboard('{Enter}')`; `fireEvent` to simulate the user is forbidden, because it does not generate the realistic sequence of focus, pointer, and keyboard events.
- **[FORBIDDEN]** Testing implementation details: internal state, CSS class names, `container.querySelector`, number of renders, hook calls, or children's props; assert only what the user perceives (text, roles, `toBeDisabled`, `toHaveAccessibleName`, `toHaveAttribute('aria-invalid', 'true')`).
- **[FORBIDDEN]** `toMatchSnapshot()` on whole pages or components: massive snapshots get updated without review; only small `toMatchInlineSnapshot()`s on stable output are allowed (e.g. serialized error messages).
- **[PATTERN]** Asynchrony: `await screen.findByRole(...)` or `await waitFor(() => { expect(...) })` for UI that changes after network calls; `queryBy*` only to assert that an element is absent; no side effects inside `waitFor`.
- **[FORBIDDEN]** Arbitrary waits (`setTimeout`, `sleep`, `page.waitForTimeout()`), dependence on execution order, and mutable data shared between tests: control time with `vi.useFakeTimers({ shouldAdvanceTime: true })` and `vi.setSystemTime()` (with `userEvent.setup({ advanceTimers: vi.advanceTimersByTime })`) or with `page.clock` in Playwright.
- **[MANDATORY]** Network mocked with MSW 2: handlers with `http.get`/`http.post` and `HttpResponse.json()` from `msw`, `setupServer()` from `msw/node` with `server.listen({ onUnhandledRequest: 'error' })` in `beforeAll`, `server.resetHandlers()` in `afterEach`, and `server.close()` in `afterAll`, per-test overrides with `server.use()`; replacing `global.fetch` by hand is forbidden.
- **[PATTERN]** Server Actions tested as async functions: `vi.mock('server-only', () => ({}))`, `vi.mock('next/cache')`, session and repository mocks; build a real `FormData` and verify the typed result for a missing session, invalid input, another tenant's resource, and the success case with `revalidateTag` called on the expected tag.
- **[PATTERN]** Async Server Components are not supported by Vitest/RTL: do not use `render(await Page(...))`; cover them with Playwright and unit-test the Data Access Layer, the DTO mappers, and the leaf Client Components.
- **[MANDATORY]** Automated accessibility: in e2e `new AxeBuilder({ page }).withTags(['wcag2a', 'wcag2aa', 'wcag21a', 'wcag21aa', 'wcag22aa']).analyze()` with `expect(results.violations).toEqual([])` on every key page; in unit tests `vitest-axe` or `jest-axe` with `toHaveNoViolations()` on complex components (dialog, combobox, form).
- **[PATTERN]** Playwright: semantic locators (`page.getByRole`, `page.getByLabel`), web-first assertions with auto-retry (`await expect(locator).toBeVisible()`, `toHaveURL`, `toHaveText`), `baseURL` and `webServer` in `playwright.config.ts` on `next build && next start`, authentication reused via a setup project and `storageState`.
- **[CONFIGURATION]** Vitest: `environment: 'jsdom'`, `globals: true` (needed for RTL's automatic cleanup, otherwise add `afterEach(cleanup)`), `setupFiles: ['./vitest.setup.ts']` with `import '@testing-library/jest-dom/vitest'`, the `@vitejs/plugin-react` and `vite-tsconfig-paths` plugins for the `@/` alias, `clearMocks: true`.
- **[CONFIGURATION]** Coverage with `@vitest/coverage-v8` and blocking `coverage.thresholds` in CI (e.g. `{ lines: 80, functions: 80, statements: 80, branches: 75 }`), excluding generated files, `*.config.*`, `app/**/page.tsx`, and `app/**/layout.tsx` already covered by e2e tests.
- **[PATTERN]** A `renderWithProviders()` helper that mounts the real providers (a new `QueryClient` per test with `retry: false`, theme, i18n) instead of mocking every hook; no state shared between one test and the next.
- **[TESTING]** Every bug fix includes a regression test that fails before the fix; test names describe the expected behavior (`it('shows an error if the email is already registered')`), never `it('works')`.
- **[CONFIGURATION]** Playwright in CI: `forbidOnly: !!process.env.CI`, `retries: process.env.CI ? 2 : 0`, `trace: 'on-first-retry'`; a test that passes only on retry is flaky and must be fixed or quarantined with a ticket, not silenced with `test.skip`.
- **[REFERENCE]** See `EXAMPLES.md` in this folder for reference anti-patterns and best practices.
