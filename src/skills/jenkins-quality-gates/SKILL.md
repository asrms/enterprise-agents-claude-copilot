# Skill: Jenkins Quality Gates

## Implementation Rules:
- **[ARCHITECTURE]** Quality gates are blocking stages that precede any push or promotion, in increasing order of cost: compilation and unit tests, coverage, static analysis, SonarQube Quality Gate, dependency SCA, image build, image scan, deploy; a failed gate stops the pipeline and no artifact is promoted.
- **[MANDATORY]** Publish tests with `junit testResults: '**/target/surefire-reports/*.xml, **/target/failsafe-reports/*.xml', allowEmptyResults: false` in the test stage's `post { always { } }`: zero reports means tests were not run or the pattern is wrong, and must fail the build.
- **[MANDATORY]** Coverage with `recordCoverage(tools: [[parser: 'JACOCO', pattern: '**/target/site/jacoco/jacoco.xml']], qualityGates: [[metric: 'LINE', baseline: 'PROJECT', threshold: 80.0, criticality: 'FAILURE'], [metric: 'BRANCH', baseline: 'PROJECT', threshold: 70.0, criticality: 'FAILURE']])` and an additional gate on `baseline: 'MODIFIED_LINES'` for new code in PRs.
- **[MANDATORY]** The quality gates of `junit`, `recordCoverage`, and `recordIssues` set the build result (UNSTABLE or FAILURE) but do not stop execution: enable `options { skipStagesAfterUnstable() }` and right after publishing check `currentBuild.currentResult` with `error`, directly or through a library global var.
- **[PATTERN]** SonarQube analysis with `withSonarQubeEnv('sonarqube') { sh 'mvn -B -ntp sonar:sonar -Dsonar.projectKey=payments-api' }` (installation, URL, and token defined in JCasC; `sonar-maven-plugin` version pinned in `pluginManagement`) and waiting in a separate stage without an agent with `timeout(time: 10, unit: 'MINUTES') { waitForQualityGate abortPipeline: true }`.
- **[CONFIGURATION]** In SonarQube configure the webhook to `https://jenkins.acme.internal/sonarqube-webhook/`: without the webhook `waitForQualityGate` waits until the timeout; the project's Quality Gate is based on "New Code" conditions and must not be replaced with permissive gates.
- **[FORBIDDEN]** `waitForQualityGate` without `timeout`, with `abortPipeline: false` without checking `status`, or replaced with `sleep`; tokens passed in plaintext with `-Dsonar.login` or `-Dsonar.token` instead of `withSonarQubeEnv`, which injects `SONAR_HOST_URL` and `SONAR_AUTH_TOKEN`.
- **[PATTERN]** Static analysis with Warnings NG: `recordIssues(enabledForFailure: true, tools: [java(), spotBugs(pattern: '**/target/spotbugsXml.xml'), checkStyle(pattern: '**/target/checkstyle-result.xml')], qualityGates: [[threshold: 1, type: 'NEW', criticality: 'FAILURE'], [threshold: 1, type: 'TOTAL_ERROR', criticality: 'FAILURE']])`: no new warnings and no total errors.
- **[MANDATORY]** SCA with a pinned OWASP Dependency-Check (`mvn org.owasp:dependency-check-maven:12.1.0:check -DfailBuildOnCVSS=7 -Dformat=ALL`), the NVD API key passed with `withCredentials`, and the database cached on a volume (`<dataDirectory>` in the pom); suppressions only in a versioned `dependency-check-suppressions.xml`, with a justification and an `until` expiry attribute.
- **[MANDATORY]** Trivy on the source (`trivy fs --scanners vuln,secret,misconfig --severity HIGH,CRITICAL --ignore-unfixed --exit-code 1 .`) and on the just-pushed image by digest (`trivy image --severity HIGH,CRITICAL --ignore-unfixed --exit-code 1 "$IMAGE_REPO@$IMAGE_DIGEST"`), never by tag; exceptions only in a versioned `.trivyignore` with a comment and an `exp:` expiry.
- **[FORBIDDEN]** `|| true`, `set +e`, `--exit-code 0`, `catchError(buildResult: 'SUCCESS', stageResult: 'UNSTABLE')`, an ignored `sh(returnStatus: true)`, `-DskipTests`, `-Dmaven.test.failure.ignore=true`, `failBuildOnCVSS=11`, `allowEmptyResults: true`: they make the gate decorative and hide failures.
- **[PATTERN]** Fail fast: cheap gates first (compilation, lint, unit tests) and expensive ones later (SonarQube, SCA, image); independent checks in `parallel` with `failFast true`; report publishing in `post { always }` so results are available even when the stage fails.
- **[PATTERN]** Integration tests (Failsafe, `mvn verify -Pintegration`) with ephemeral dependencies as sidecar containers of the pod (e.g. `postgres:16.6`) instead of shared environments, reports in `**/target/failsafe-reports/*.xml` published with the same `junit`.
- **[SECURITY]** Security reports published and archived for audit: `recordIssues(tools: [owaspDependencyCheck(pattern: '**/target/dependency-check-report.json'), trivy(pattern: 'trivy-*.json')])` and `archiveArtifacts artifacts: '**/target/dependency-check-report.html, trivy-*.json', allowEmptyArchive: false`.
- **[SECURITY]** Registries and scanners authenticated with dedicated read-only credentials: `withCredentials([usernamePassword(credentialsId: 'harbor-payments-pull', usernameVariable: 'TRIVY_USERNAME', passwordVariable: 'TRIVY_PASSWORD')])` for `trivy image`.
- **[PERFORMANCE]** Scan databases cached on a PVC (`--cache-dir /cache/trivy`, Dependency-Check's `<dataDirectory>`) and an internal mirror of the Trivy DB (`--db-repository harbor.acme.internal/mirror/trivy-db`) to avoid downloads on every build and NVD and GHCR rate limits.
- **[CONFIGURATION]** Thresholds (coverage, CVSS, severity) defined centrally in the shared library or in `ci/quality.yaml` read with `readYaml`; lowering them requires a PR approved by the platform or security team, never an override via `parameters`.
- **[TESTING]** Test the gates themselves: a test PR with a failing test, coverage below threshold, or a known vulnerable dependency must fail the build; JenkinsPipelineUnit tests on the global var that assert `abortPipeline: true` and `allowEmptyResults: false`.
- **[REFERENCE]** See `EXAMPLES.md` in this folder for reference anti-patterns and best practices.
