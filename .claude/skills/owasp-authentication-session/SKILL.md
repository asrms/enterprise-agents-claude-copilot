# Skill: Authentication and Session Management (OWASP A07:2021)

## Implementation Rules:
- **[ARCHITECTURE]** Prefer a standard IdP (OIDC Authorization Code + PKCE with Keycloak, Entra ID, Auth0, Okta) over home-made authentication; for SPAs use the BFF (Backend for Frontend) pattern with a server-side session and cookies, keeping OAuth tokens on the server.
- **[MANDATORY]** Hash passwords with Argon2id m=19456 KiB, t=2, p=1 (OWASP Password Storage Cheat Sheet): Spring `new Argon2PasswordEncoder(16, 32, 1, 19456, 2)`, Python argon2-cffi `PasswordHasher(time_cost=2, memory_cost=19456, parallelism=1)`, Node `argon2.hash(pw, { type: argon2.argon2id, memoryCost: 19456, timeCost: 2, parallelism: 1 })`; accepted alternatives: scrypt N=2^17 r=8 p=1, bcrypt cost ≥ 10 (input limited to 72 bytes), PBKDF2-HMAC-SHA256 with 600,000 iterations only if FIPS 140 is required.
- **[FORBIDDEN]** MD5, SHA-1, plain SHA-256/SHA-512 or with a static salt for passwords, reversible password encryption, `NoOpPasswordEncoder` or the `{noop}` prefix in `DelegatingPasswordEncoder`, comparing hashes with `equals`/`==` (CWE-916, CWE-328).
- **[MANDATORY]** Transparent rehash at login when parameters change: Spring `PasswordEncoder.upgradeEncoding`, argon2-cffi `check_needs_rehash`, Node `argon2.needsRehash`; migration from legacy hashes by wrapping (`argon2id(sha1_legacy)`) without waiting for every user to log in.
- **[MANDATORY]** Password policy per NIST SP 800-63B: minimum 15 characters if the password is the only factor, 8 if combined with MFA; maximum allowed ≥ 64; no mandatory composition rules or periodic expiry; block compromised passwords via the HIBP Pwned Passwords range API (`https://api.pwnedpasswords.com/range/<first 5 hex of SHA-1>`, k-anonymity).
- **[MANDATORY]** MFA with TOTP (RFC 6238, ±1 step tolerance of 30 s, rejection of reuse of the same code) or WebAuthn/passkeys, mandatory for privileged accounts; step-up authentication for changing email, password, MFA method, and for high-risk operations; single-use recovery codes stored as hashes.
- **[MANDATORY]** Rate limiting and progressive lockout per account and per IP (e.g. after 5 failed attempts in 15 minutes per account, exponential delay up to 15 minutes; 100 attempts/minute per IP): Spring with Bucket4j, FastAPI with `slowapi`, Node with `rate-limiter-flexible` on Redis; timed unlock, never a permanent lockout exploitable as DoS (CWE-307).
- **[SECURITY]** Against credential stuffing combine limits per IP/ASN/device, compromised password checks, MFA, and notification of logins from new devices; every failed login is a structured security event.
- **[MANDATORY]** Account enumeration (CWE-204): same status and same message ("Invalid credentials") for a non-existent user and a wrong password; uniform timing by verifying a precomputed dummy hash anyway; sign-up and "forgot password" always respond identically (e.g. 202 "If the address is registered you will receive an email") with the email sent asynchronously.
- **[MANDATORY]** Session fixation (CWE-384): regenerate the session ID at login and on every privilege change — Spring Security `sessionManagement(s -> s.sessionFixation(f -> f.changeSessionId()))` (default), servlet `request.changeSessionId()`, express-session `req.session.regenerate()`, FastAPI with server-side sessions a new ID `secrets.token_urlsafe(32)` and invalidation of the previous one; on logout invalidate the session on the server, not just the cookie.
- **[MANDATORY]** Session cookies `HttpOnly; Secure; SameSite=Lax` (`Strict` for back offices) with the `__Host-` prefix (requires `Secure`, `Path=/`, no `Domain`); Spring Boot `server.servlet.session.cookie.http-only=true`, `secure=true`, `same-site=lax`; idle timeout of 15–30 minutes and absolute timeout of 8–12 hours depending on risk.
- **[MANDATORY]** JWT validation with a server-side fixed algorithm and mandatory claims: PyJWT `jwt.decode(t, key, algorithms=["RS256"], audience=AUD, issuer=ISS, options={"require": ["exp", "iat", "iss", "aud"]})`, Node `jose` `jwtVerify(token, JWKS, { algorithms: ['RS256'], issuer, audience, maxTokenAge: '15m' })`, Spring `NimbusJwtDecoder.withJwkSetUri(uri).jwsAlgorithm(SignatureAlgorithm.RS256)` with `JwtValidators.createDefaultWithIssuer(iss)` plus an `aud` validator; clock skew ≤ 60 s.
- **[FORBIDDEN]** Accepting `alg: none`, choosing the algorithm or key from the token header (`jku`, `x5u`, `kid` pointing to non-allowlisted URLs), `jwt.decode(token, key, options={"verify_signature": False})` or `jsonwebtoken.decode()` for access decisions, `jwt.verify(token, key)` without `algorithms` (HS256/RS256 confusion: public key used as HMAC secret; CVE-2022-23541 in jsonwebtoken < 9), HMAC secrets < 256 bits or hardcoded (CWE-347).
- **[MANDATORY]** Short-lived access tokens (5–15 minutes); an opaque refresh token, stored as a SHA-256 hash, rotated on every use with reuse detection (reusing an already-rotated refresh token revokes the entire token family), revoked on logout and password change.
- **[FORBIDDEN]** JWTs or refresh tokens in `localStorage`/`sessionStorage` (readable by any XSS, CWE-922) and tokens in URLs or query strings (they end up in logs, history, and the `Referer` header); use `HttpOnly; Secure; SameSite` cookies or the BFF pattern.
- **[MANDATORY]** Password reset (CWE-640): a CSPRNG token ≥ 128 bits (`secrets.token_urlsafe(32)`, `crypto.randomBytes(32)`, 32-byte `SecureRandom`), stored as a SHA-256 hash, expiry ≤ 30 minutes, single use with atomic consumption, invalidation of all sessions after the reset; link built from a configured base URL, never from the `Host` header.
- **[SECURITY]** Changing password or email requires the current password or a recent re-authentication (CWE-620) and triggers a notification to the previous address; the email change takes effect only after confirmation at the new address.
- **[REVIEW]** Grep: `verify_signature.*False`, `algorithms=\[.*none`, `jwt\.decode\(`, `localStorage\.setItem\(.*[Tt]oken`, `MessageDigest\.getInstance\("(MD5|SHA-1|SHA-256)"\)` near `password`, `hashlib\.(md5|sha1|sha256)\(.*pass`, `NoOpPasswordEncoder`, `sessionFixation\(.*none\(\)`, `httpOnly:\s*false`, `secure:\s*false`, `random\.(randint|choice)` or `Math\.random` used for tokens.
- **[PERFORMANCE]** Tune hashing parameters to stay ≤ 500 ms per verification on production hardware and limit concurrent verifications (semaphore/bulkhead), because Argon2id with 19 MiB per attempt can exhaust memory under attack; cache the JWKS with a TTL (`createRemoteJWKSet` and `NimbusJwtDecoder` already do this).
- **[CONFIGURATION]** Signing keys and secrets in KMS/Vault with rotation via `kid` and JWKS; no `jwt.secret`, `SECRET_KEY`, or private key in `application.yml`, `.env`, or versioned sources.
- **[TESTING]** Mandatory tests: token with `alg: none`, altered signature, past `exp`, or wrong `aud` → 401; non-existent user and wrong password → identical response; different session ID before and after login; reuse of the reset token → 400; reuse of a rotated refresh token → revocation of the family; exceeding the attempt threshold → 429.
- **[CWE]** CWE-287, CWE-307, CWE-384, CWE-613, CWE-640, CWE-620, CWE-521, CWE-798 → A07:2021; CWE-916 (weak hash) and CWE-347 (unverified signature) → A02:2021; CWE-614/CWE-1004 (cookie flags) → A05:2021; CWE-922 (token in browser storage) → A01:2021; CWE-204 for enumeration.
