# Skill: Jenkins Declarative Pipeline (Jenkinsfile in SCM, Multibranch)

## Implementation Rules:
- **[ARCHITECTURE]** Use Declarative Pipeline (`pipeline { ... }`) exclusively, versioned as a `Jenkinsfile` in the repository root and run by a Multibranch job or an Organization Folder; Scripted Pipeline (`node { ... }`) is allowed only inside shared libraries.
- **[ARCHITECTURE]** Declare `agent none` at the top level and an `agent` for every stage that does work; sequential stages that must share workspace and cache are grouped under a parent stage with a single `agent` and nested `stages { }`; stages without an agent (approvals, `milestone`, `waitForQualityGate`, notifications) occupy no executor.
- **[MANDATORY]** A top-level `options` block with at least `timeout(time: 45, unit: 'MINUTES')`, `buildDiscarder(logRotator(numToKeepStr: '30', artifactNumToKeepStr: '5'))`, and `timestamps()`; the top-level `timeout` also covers `input` waits, so in release pipelines size it to the approval window and pair it with tight per-stage timeouts.
- **[MANDATORY]** In branch and PR CI pipelines add `disableConcurrentBuilds(abortPrevious: true)`; in release pipelines on `main` do not use `abortPrevious` (it would abort a deployment in progress) and govern concurrency with `milestone` and `lock`.
- **[PATTERN]** Use `skipDefaultCheckout()` when checkout is handled explicitly (`checkout scm` or shallow clone) or when stages do not need the sources, and `checkoutToSubdirectory('src')` only if the layout requires it.
- **[MANDATORY]** Every stage that calls external systems has its own `options { timeout(time: 10, unit: 'MINUTES') }` (or `timeout(time: 15, unit: 'MINUTES', activity: true)` for steps with continuous output); no stage may hang until the global timeout.
- **[PATTERN]** Express conditions with native `when` directives: `branch 'main'`, `changeRequest target: 'main'`, `buildingTag()`, `tag pattern: 'v\\d+\\.\\d+\\.\\d+', comparator: 'REGEXP'`, `changeset 'services/api/**'`, `triggeredBy 'TimerTrigger'`, combined with `allOf`/`anyOf`/`not`; use `expression { }` only when no directive is sufficient.
- **[MANDATORY]** In every `when` of a stage with an `agent` set `beforeAgent true`, and `beforeInput true` in stages with `input`: this way no pods are provisioned and no approvals are requested for stages that will be skipped.
- **[PATTERN]** Stage-level `post` for reports (`always { junit ... }`, `always { recordIssues ... }`) and pipeline-level `post` for notifications (`failure`, `unstable`, `fixed`, `regression`); `success` for archiving and fingerprinting, `cleanup` (run last) for releasing external resources.
- **[PATTERN]** Top-level `environment` for shared constants (`IMAGE_REPO = 'harbor.acme.internal/payments/api'`) and credentials (`SONAR = credentials('sonar-token')`), stage-level for local values; do not redefine built-in variables such as `BRANCH_NAME`, `CHANGE_ID`, `GIT_COMMIT`, `BUILD_NUMBER`, `WORKSPACE`.
- **[PATTERN]** Use `parameters` only for non-sensitive operational inputs with a safe default, for example `booleanParam(name: 'RUN_E2E', defaultValue: false, description: 'Also run the end-to-end tests')` or `choice(name: 'LOG_LEVEL', choices: ['INFO', 'DEBUG'], description: 'Test log level')`; in Multibranch, parameters are registered only after the branch's first run.
- **[FORBIDDEN]** Complex Groovy logic in the Jenkinsfile: `def` methods outside `pipeline`, loops, regex or `JsonSlurper` parsing, `try/catch`, classes, `Jenkins.instance`, `currentBuild.rawBuild`; the `script { }` block is allowed for a few lines (assigning `env.X` from `readJSON`/`readMavenPom`, calling a global var), everything else belongs in the shared library.
- **[FORBIDDEN]** Top-level `agent any` or `agent { label 'built-in' }`, `input` as a step inside a stage with an agent, `node { }` inside `script { }`, `sleep` to wait for external systems (use webhooks, `waitUntil`, or `retry` inside `timeout`).
- **[FORBIDDEN]** `catchError`, `warnError`, or `try/catch` that turn an error into SUCCESS, `sh(returnStatus: true)` without an explicit exit code check, `currentBuild.result = 'SUCCESS'` forced in `post`.
- **[PATTERN]** Reuse the platform's standard steps with `@Library('platform-lib@v2.3.1') _` (or the `libraries { lib('platform-lib@v2.3.1') }` directive) and calls with named parameters such as `mavenBuild(goals: 'verify')`; the Jenkinsfile describes the flow, the library implements the details.
- **[PATTERN]** Stable, short, and unique stage names ("Build", "Unit Test", "Quality Gate", "Image", "Deploy staging"): they are the keys for Stage View, Pipeline Graph View, per-stage metrics, and Warnings NG reports.
- **[SECURITY]** Strings passed to `sh` that contain sensitive variables use single quotes (`sh 'curl -u "$REG_USR:$REG_PSW" https://harbor.acme.internal/api/v2.0/projects'`); `"..."` GStrings are allowed only for non-secret values known to Groovy.
- **[PERFORMANCE]** Run independent stages in `parallel` with `failFast true` or `options { parallelsAlwaysFailFast() }`, and version combinations with `matrix`; remember that a stage with `parallel` or `matrix` cannot itself contain another one.
- **[CONFIGURATION]** `triggers` in the Jenkinsfile only for `H`-hashed schedules restricted to one branch, for example `cron(env.BRANCH_NAME == 'main' ? 'H 2 * * 1-5' : '')`; for SCM events use webhooks, never `pollSCM`.
- **[CONFIGURATION]** Multibranch jobs defined as code (Job DSL or JCasC `jobs:`) with Script Path `Jenkinsfile`, branch, PR, and tag discovery, and an orphaned-branch cleanup strategy; no jobs configured by hand from the UI.
- **[TESTING]** Validate the syntax before merging with `curl -X POST -F "jenkinsfile=<Jenkinsfile" "$JENKINS_URL/pipeline-model-converter/validate"` or with the `declarative-linter` CLI command; Replay is only for experimenting, and the change must then be committed back to SCM.
- **[TESTING]** Verify the stage flow for branches, PRs, and tags with JenkinsPipelineUnit (`DeclarativePipelineTest`), asserting which stages run or are skipped.
- **[REFERENCE]** See `EXAMPLES.md` in this folder for reference anti-patterns and best practices.
