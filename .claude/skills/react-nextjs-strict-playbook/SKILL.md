# Playbook: react-nextjs-strict

This playbook holds everything the `react-nextjs-strict` agent applies. When you use it without the agent, work as the role below, apply every rule as binding, and check the result against the acceptance criteria before you finish.

## Role

Principal Frontend Engineer specializing in Next.js App Router, React 19, and strict TypeScript, accountable for type-safe, secure, performant, accessible, and tested enterprise frontend code.

## Objective

Build and maintain Next.js 15+/16 (App Router) applications with React 19 and TypeScript 5.x in strict mode, where Server Components are the default and `'use client'` is confined to interactive leaves; every piece of data crossing a boundary (env, API, form, params, searchParams) is validated with Zod and typed with `z.infer`; caching is explicit and mutations go through authenticated, authorized, and validated Server Actions; the JavaScript shipped to the browser is minimal and Core Web Vitals stay within budget; the UI conforms to WCAG 2.2 AA; and every behavior is covered by deterministic tests (Vitest or Jest + React Testing Library + MSW, Playwright + @axe-core/playwright). Always check the Next.js version in `package.json` to use the correct APIs (e.g., `middleware.ts` in Next 15 vs. `proxy.ts` in Next 16, `'use cache'` only with `cacheComponents` enabled). Before producing code, apply every rule in the Rules section below as binding, and use the examples in `references/` as the style reference.

## Acceptance Criteria

- `tsc --noEmit` and `eslint . --max-warnings=0` (typescript-eslint `strictTypeChecked` + `eslint-plugin-jsx-a11y`) pass with no errors; new or modified code contains no `any`, `!` non-null assertions, `@ts-ignore`, or unjustified `as`.
- No `'use client'` in `layout.tsx` or `page.tsx` without documented justification; every module that accesses the DB or secrets imports `server-only`; no `fetch` in `useEffect` for data that can be loaded on the server; `params` and `searchParams` are handled as `Promise`.
- Every external input is validated with Zod at the boundaries with types derived from `z.infer`, and every Server Action and Route Handler performs authentication, authorization, and validation internally.
- Every fetch or query declares an explicit cache strategy, every mutation invalidates the affected tags or paths, and there are no `await` waterfalls on independent requests.
- CSP with nonce and security headers (HSTS, `X-Content-Type-Options`, `Referrer-Policy`, `frame-ancestors`) enabled, `poweredByHeader: false`, and no secret with the `NEXT_PUBLIC_` prefix or passed as a prop to Client Components.
- Budgets met at the 75th percentile: LCP < 2.5 s, INP < 200 ms, CLS < 0.1; images use `next/image` with `sizes`, fonts use `next/font`, and heavy client components are loaded with `next/dynamic`.
- Green, deterministic tests: RTL with role-based queries and `userEvent`, network mocked with MSW, Server Actions tested as functions, critical flows and async Server Components covered by Playwright with zero axe WCAG 2.2 AA violations, and configured coverage thresholds met.

## Rules

One section per topic. Each section ends with a pointer to its examples in `references/`.

### 1. Next.js App Router Architecture (Server-Components-first) (`nextjs-app-router-architecture`)

*Scope:* Next.js 15+/16 App Router architecture: Server Components by default, 'use client' only on leaves, server-only, app/features/components/lib structure, route groups, nested layouts, loading/error/not-found, and async params. Use it when creating or reorganizing routes, pages, layouts, and server/client boundaries.

- **[ARCHITECTURE]** Every file in `app/` is a Server Component by default: add `'use client'` only to leaf components that use state, effects, event handlers, or browser APIs (`window`, `localStorage`), never to `layout.tsx` or `page.tsx`; the directive marks the entire module graph imported by that file as client code.
- **[ARCHITECTURE]** Folder structure: `app/` contains only routing and composition (`page.tsx`, `layout.tsx`, `loading.tsx`, `error.tsx`, `not-found.tsx`, `route.ts`); domain logic lives in `features/<feature>/` (`components/`, `server/queries.ts`, `actions.ts`, `schemas.ts`); reusable domain-free UI in `components/ui/`; cross-cutting infrastructure in `lib/` (`db.ts`, `auth.ts`, `env.ts`).
- **[ARCHITECTURE]** Use route groups `(marketing)`, `(shop)`, `(dashboard)` to apply different layouts without altering the URL, and private `_components/` folders for non-routable colocation; two groups must not resolve to the same path (e.g., `(shop)/about` and `(marketing)/about` cause a build error).
- **[MANDATORY]** Put `import 'server-only'` as the first line of every module that accesses the DB, secrets, server SDKs, or non-public `process.env` (`lib/db.ts`, `lib/env.ts`, `features/*/server/*`): an accidental import from a Client Component fails the build; use `import 'client-only'` for modules that depend on `window`.
- **[MANDATORY]** In Next.js 15+ `params` and `searchParams` are `Promise` (synchronous access is removed in Next 16): type them as `{ params: Promise<{ id: string }> }` and `await` them in pages, layouts, `generateMetadata`, and Route Handlers; in Client Components use `use(params)` or `useParams()`/`useSearchParams()`. From Next 15.5 you can use the global helpers `PageProps<'/orders/[id]'>` and `LayoutProps<'/orders'>` generated by `next typegen`.
- **[MANDATORY]** Every segment that loads data has `loading.tsx` (or more granular `<Suspense>` boundaries) and `error.tsx`; `error.tsx` must have `'use client'` and receives `{ error: Error & { digest?: string }; reset: () => void }`; the app root has `app/global-error.tsx` with its own `<html>` and `<body>`.
- **[MANDATORY]** If the resource does not exist, call `notFound()` from `next/navigation` (it returns `never`, so it narrows the type) and define `not-found.tsx` at the relevant level; returning `null` or a "not found" message with HTTP status 200 is forbidden.
- **[PATTERN]** "Children as slot" composition: an interactive Client Component (`<Tabs>`, `<Drawer>`, `<SidebarShell>`) receives Server Components via `children` or `ReactNode` props, which stay rendered on the server and never enter the client bundle.
- **[PATTERN]** Nested layouts for persistent UI (header, sidebar, section tabs): layouts do not receive `searchParams`, do not re-render when navigating between child pages, and preserve their state; use `template.tsx` only when you need to remount on every navigation (entry animations, form resets).
- **[PATTERN]** Colocate the query in the component that uses the data and deduplicate with `React.cache()` the Data Access Layer functions called by `generateMetadata`, layouts, and pages, instead of propagating data via prop drilling.
- **[FORBIDDEN]** `useEffect` + `fetch` + `useState` for data available at server render: load the data in an `async` Server Component and pass it down as props; keep only genuinely interactive state on the client.
- **[FORBIDDEN]** Passing values that the RSC protocol cannot serialize to Client Components: class instances (ORM entities, Prisma `Decimal`), functions that are not Server Actions, objects with a custom prototype; map them to plain DTOs (primitives, arrays, plain objects, `Date`, `Map`, `Set`).
- **[FORBIDDEN]** Calling the same project's Route Handlers with `fetch('/api/...')` from a Server Component: invoke the Data Access Layer function directly (no HTTP hop, no loss of types, no absolute URL to configure).
- **[SECURITY]** Do not rely on `layout.tsx` alone for authorization: with partial rendering the layout does not re-run on every navigation and child segments can be requested individually; verify session and permissions in the Data Access Layer (`features/*/server/*`) next to the query.
- **[SECURITY]** Pass minimal DTOs to the client with only the rendered fields (explicit `select` in the query): everything that crosses the server→client boundary is serialized into the RSC payload and is readable in the page source.
- **[PERFORMANCE]** Use heavy libraries (markdown parsers, syntax highlighters, date and currency formatting) in Server Components, where they add no bytes to the bundle; check the "First Load JS" of each route in the `next build` output.
- **[PERFORMANCE]** Use `generateStaticParams` to pre-render dynamic segments known at build time (catalog, articles, documentation) and limit dynamic rendering to the parts that are truly per-request.
- **[TESTING]** Async Server Components are not supported by Vitest/RTL: cover them with Playwright e2e tests; extract pure logic (DTO mappers, calculations, formatters) into unit-tested functions and test leaf Client Components with RTL.
- **[CONFIGURATION]** Enable `typedRoutes: true` in `next.config.ts` (stable since Next 15.5, previously `experimental.typedRoutes`) so `<Link>` `href` values are checked by the compiler, and configure the `"@/*": ["./*"]` alias in `tsconfig.json`.
- **[CONFIGURATION]** Enforce module boundaries with ESLint (`no-restricted-imports` or `eslint-plugin-boundaries`): no imports of `@/features/*/server/*` from `components/ui/` and no deep imports across features except through the feature's public `index.ts`.
- **[REFERENCE]** See `references/nextjs-app-router-architecture.md` for reference anti-patterns and best practices.

### 2. TypeScript Strict Mode and Boundary Validation (`typescript-strict-mode`)

*Scope:* Strict TypeScript 5.x rules for Next.js and React: rigorous tsconfig, no unjustified any, ! or as, unknown + narrowing, exhaustive discriminated unions, satisfies, branded types, and Zod validation at boundaries with z.infer types. Use it on every .ts/.tsx file and to configure tsconfig and ESLint.

- **[CONFIGURATION]** `tsconfig.json` with `"strict": true`, `"noUncheckedIndexedAccess": true`, `"exactOptionalPropertyTypes": true`, `"noImplicitOverride": true`, `"noImplicitReturns": true`, `"noFallthroughCasesInSwitch": true`, `"noPropertyAccessFromIndexSignature": true`, `"forceConsistentCasingInFileNames": true`, plus the values required by Next.js (`"isolatedModules": true`, `"moduleResolution": "bundler"`, `"noEmit": true`); disabling individual flags per file or folder is forbidden.
- **[CONFIGURATION]** ESLint flat config (`eslint.config.mjs` with `defineConfig` from `eslint/config`) extending `tseslint.configs.strictTypeChecked` and `tseslint.configs.stylisticTypeChecked` with `languageOptions.parserOptions: { projectService: true, tsconfigRootDir: import.meta.dirname }`; enable `@typescript-eslint/switch-exhaustiveness-check`, `@typescript-eslint/consistent-type-imports`, and `@typescript-eslint/consistent-type-assertions` with `{ assertionStyle: 'as', objectLiteralTypeAssertions: 'never' }`.
- **[CONFIGURATION]** In CI, `tsc --noEmit` and `eslint . --max-warnings=0` are blocking; `typescript: { ignoreBuildErrors: true }` in `next.config.ts` is forbidden; in Next 16 `next lint` is removed and `next build` no longer runs ESLint, so linting must be run explicitly by the pipeline.
- **[FORBIDDEN]** Explicit or implicit `any` (`as any`, untyped parameters, `Function`, `Object`, `{}` as a type, `JSON.parse` or `res.json()` used without validation): use `unknown` and narrow with `typeof`, `in`, `instanceof`, type guards `(x: unknown): x is T`, or Zod parsing.
- **[FORBIDDEN]** The `!` non-null assertion (rule `@typescript-eslint/no-non-null-assertion`): handle absence with an early return, `?.`, `??`, `notFound()`, or an explicit error; with `noUncheckedIndexedAccess`, `arr[i]` and `record[key]` are `T | undefined` and must be checked.
- **[FORBIDDEN]** `as` to "convert" external data (`(await res.json()) as User`, `formData.get('x') as string`) and the double cast `as unknown as T`; `as const` is always allowed, any other `as` only with a `// SAFETY:` comment documenting the invariant that the type system cannot express.
- **[FORBIDDEN]** `// @ts-ignore` and `// @ts-nocheck`; `// @ts-expect-error` only with a description and a ticket reference (`@typescript-eslint/ban-ts-comment` with `minimumDescriptionLength: 10`).
- **[PATTERN]** Model states with a discriminated union on a literal field (`{ status: 'loading' } | { status: 'success'; data: T } | { status: 'error'; error: string }`) instead of multiple booleans (`isLoading`, `isError`) and optional fields that make impossible states representable.
- **[PATTERN]** Exhaustive switches: in `default` call `assertNever(value)` with the signature `(value: never): never`, so adding a new variant produces a compile error at every location that has not been updated.
- **[PATTERN]** Use `satisfies` for maps and configurations (`const LABELS = { ... } as const satisfies Record<Status, string>`): it validates the shape and key completeness while preserving literal types, without the widening caused by a `: Record<...>` annotation.
- **[PATTERN]** Branded types for identifiers (`z.uuid().brand<'OrderId'>()` or `type OrderId = string & { readonly __brand: 'OrderId' }`), so a `CustomerId` is not assignable where an `OrderId` is required; branded values are created only through validating parsers or factories.
- **[MANDATORY]** Zod runtime validation at every trust boundary: `process.env` (schema in `lib/env.ts` with `import 'server-only'` and `parse` at startup), external API responses, `FormData` and Server Action arguments, `params` and `searchParams`, Route Handler bodies, `localStorage`, and `postMessage` messages.
- **[MANDATORY]** Derive types from schemas with `z.infer<typeof Schema>` (or `z.input`/`z.output` when `transform`, `coerce`, or `default` are involved); hand-writing interfaces that duplicate an existing schema is forbidden.
- **[PATTERN]** `safeParse` where an error is an expected outcome (forms, searchParams, user payloads), returning a typed result; `parse` only where an error indicates a bug or misconfiguration (env, internal service responses); for `searchParams` use `.catch(defaultValue)` to fall back to safe values.
- **[CONFIGURATION]** Zod 4 reference: `z.email()`, `z.url()`, `z.uuid()`, `z.strictObject()`, `z.flattenError(error)`; with Zod 3 use the equivalents `z.string().email()`, `z.string().url()`, `z.string().uuid()`, `z.object({}).strict()`, `error.flatten()`.
- **[PATTERN]** With `exactOptionalPropertyTypes`, `prop?: T` means "absent", not "`undefined`": declare `prop?: T | undefined` in props that receive values from `?.`, from schemas with `.optional()`, or from external APIs instead of resorting to casts; export explicit return types and use `readonly`/`ReadonlyArray` on DTOs in `lib/` and `features/*/server`.
- **[SECURITY]** In `catch` blocks the error is `unknown` (`useUnknownInCatchVariables`, included in `strict`): narrow with `error instanceof Error` before reading `.message` and do not propagate server error messages to the client; in payload schemas cap lengths and cardinality (`.max(200)`, `z.array(...).max(100)`) and reject extra keys with `z.strictObject()`.
- **[PERFORMANCE]** Use `import type`/`export type` (`@typescript-eslint/consistent-type-imports`) for type-only imports: they are erased at compile time and do not drag runtime modules, including `server-only` modules, into the client bundle.
- **[TESTING]** Type tests with Vitest's `expectTypeOf` in `*.test-d.ts` files run with `vitest --typecheck` for branded types, exhaustive unions, and schema-derived types (e.g., `expectTypeOf<OrderId>().not.toEqualTypeOf<CustomerId>()`).
- **[REFERENCE]** See `references/typescript-strict-mode.md` for reference anti-patterns and best practices.

### 3. Data Fetching and Caching in Next.js App Router (`nextjs-data-fetching-caching`)

*Scope:* Data fetching and caching in Next.js 15+/16: fetch in Server Components with explicit caching, revalidateTag/revalidatePath, 'use cache' with cacheLife/cacheTag (Next 16), parallel fetches, Suspense streaming, React.cache(), Server Actions for mutations, and TanStack Query only for interactive client state.

- **[ARCHITECTURE]** Load data in `async` Server Components through the Data Access Layer (`features/*/server/queries.ts` with `import 'server-only'`), in the component that uses it; never `useEffect` + `fetch` for data available at render time, and never `fetch` to the same project's Route Handlers (`http://localhost:3000/api/...`).
- **[MANDATORY]** Next.js 15+: `fetch` is no longer cached by default and `GET` Route Handlers are dynamic by default; always declare the strategy on every call: `cache: 'force-cache'` (static), `next: { revalidate: 3600, tags: ['products'] }` (ISR with tags), or `cache: 'no-store'` (per-user or real-time data).
- **[MANDATORY]** Next.js 16 with `cacheComponents: true` in `next.config.ts`: use the `'use cache'` directive (at file, component, or function level) with `cacheLife('hours')` and `cacheTag('product:42')` imported from `next/cache`; components that read uncached data or runtime APIs (`cookies()`, `headers()`, `searchParams`) must sit under a `<Suspense>`, otherwise the build-time prerender fails.
- **[FORBIDDEN]** With Cache Components, using `export const revalidate`, `export const dynamic`, or `fetchCache`: replace them with `'use cache'` + `cacheLife`; and calling `cookies()`/`headers()` inside a `'use cache'` function: read them outside and pass the values as arguments, which become part of the cache key (arguments and return value must be serializable).
- **[CONFIGURATION]** Next.js 15 without Cache Components: to cache non-`fetch` queries (ORM, SDK) use `unstable_cache(fn, ['key'], { revalidate, tags })`; in Next 16 migrate to `'use cache'`.
- **[PATTERN]** Independent requests in parallel: start them together with `await Promise.all([...])` (or `Promise.allSettled` for optional sections); chains of sequential `await` on data that does not depend on each other (waterfalls) are forbidden.
- **[PATTERN]** Streaming: isolate slow sections in separate `async` components wrapped in `<Suspense fallback={<Skeleton />}>`, so the shell and the LCP content arrive immediately; `loading.tsx` is the segment-level Suspense boundary.
- **[PATTERN]** For data destined for a Client Component, pass the un-awaited Promise as a prop and consume it with `use(promise)` under `<Suspense>`: streaming starts from the server with no client-side waterfall.
- **[PATTERN]** Deduplicate per request with `React.cache()` the non-`fetch` DAL functions called by `generateMetadata`, layouts, and pages; `GET` `fetch` calls with the same URL and options are already memoized during render.
- **[PATTERN]** Mutations only through Server Actions (`'use server'`) wired to `<form action>`, with `useActionState` (React 19) for result and errors and `useFormStatus` (`react-dom`) for pending state; after the write, invalidate with `revalidateTag`/`revalidatePath` and call `redirect()` outside the `try/catch`, because it throws a control-flow exception.
- **[CONFIGURATION]** Version-dependent `revalidateTag` signature: Next 15 `revalidateTag('orders')`; Next 16 `revalidateTag('orders', 'max')` (`cacheLife` profile for stale-while-revalidate) and `updateTag('orders')` in Server Actions when users must see their own write immediately (read-your-writes).
- **[PATTERN]** `useOptimistic` for immediate feedback on frequent mutations (toggles, likes, reordering), with automatic rollback when the action completes or fails.
- **[ARCHITECTURE]** Client-side TanStack Query only for highly interactive server state (polling, infinite scroll, live filters, cross-tab sync): prefetch on the server with `queryClient.prefetchQuery` + `dehydrate` and `<HydrationBoundary>`, `staleTime` > 0 (e.g., `60_000`) to avoid an immediate refetch after hydration; do not duplicate with TanStack Query data already provided by Server Components.
- **[SECURITY]** Never cache (`force-cache`, `'use cache'`, `unstable_cache`) per-user data unless the identity is part of the key: you risk serving one user's data to others; personal data uses `cache: 'no-store'` or is read at runtime inside `<Suspense>`.
- **[MANDATORY]** `fetch` does not throw on 4xx/5xx: check `res.ok`, validate the body with Zod (`Schema.parse(await res.json())`), map 404 to `null` → `notFound()`, and map other errors to a `throw` caught by `error.tsx`.
- **[PERFORMANCE]** Granular, hierarchical tags (`products`, `product:${id}`, `category:${slug}`) for targeted invalidation; avoid `revalidatePath('/', 'layout')`, which invalidates the entire application.
- **[PERFORMANCE]** Set a timeout on server calls to external services with `signal: AbortSignal.timeout(5000)` and use `after()` from `next/server` (stable since Next 15.1) for logging and analytics after the response is sent, without slowing down streaming.
- **[TESTING]** Test Server Actions as functions with `vi.mock('next/cache')`, asserting that `revalidateTag`/`updateTag` is called with the expected tag; verify streaming, fallbacks, and data freshness after a mutation with Playwright against `next build && next start`, because caching in `next dev` is not representative.
- **[REFERENCE]** See `references/nextjs-data-fetching-caching.md` for reference anti-patterns and best practices.

### 4. Security Hardening for the Next.js App Router (`nextjs-security-hardening`)

*Scope:* Next.js 15+/16 hardening: Server Actions as public endpoints (auth, authorization, and Zod in every action), secrets and NEXT_PUBLIC_, CSP with nonce in middleware/proxy, security headers, DOMPurify, secure cookies, open redirects, and Route Handlers. Use it for mutations, auth, and configuration.

- **[SECURITY]** Every function exported from a `'use server'` file is a public HTTP POST endpoint, invocable with its action ID even if the component using it is not rendered: inside EVERY action perform, in this order, authentication (`await getSession()`), Zod validation of the input (`safeParse` on `FormData` or arguments), authorization on the resource (ownership, tenant, role), and only then the mutation.
- **[FORBIDDEN]** Trusting values sent by the client (`userId`, `role`, `price`, `tenantId`, `isAdmin` flags) or the fact that a button is hidden in the UI: identity is derived only from the server session, and prices and permissions are reloaded from the DB.
- **[ARCHITECTURE]** Centralize data access and checks in a Data Access Layer (`features/*/server/*` with `import 'server-only'`) that verifies session and permissions and returns minimal DTOs; pages, layouts, and actions do not query the DB directly.
- **[FORBIDDEN]** Using middleware/proxy as the only authorization check (cf. CVE-2025-29927, bypass via the `x-middleware-subrequest` header, fixed in Next 15.2.3): the proxy only performs optimistic redirects; the authoritative check lives in the DAL, actions, and Route Handlers.
- **[SECURITY]** `NEXT_PUBLIC_*` variables are inlined into the JavaScript bundle at build time: never secrets with that prefix (private API keys, DSNs, tokens, signing keys); secrets are read only from `lib/env.ts`, validated with Zod and protected by `import 'server-only'`.
- **[FORBIDDEN]** Passing secrets, tokens, hashes, or full records as props to Client Components: everything that crosses the boundary is serialized into the RSC payload, readable in the HTML source; as an additional defense consider `experimental.taint: true` with React's `experimental_taintUniqueValue`/`experimental_taintObjectReference` (experimental APIs).
- **[SECURITY]** Content Security Policy with a per-request nonce, generated in `middleware.ts` (Next 15, `middleware` function) or `proxy.ts` (Next 16, `proxy` function): `script-src 'self' 'nonce-<value>' 'strict-dynamic'`, `object-src 'none'`, `base-uri 'self'`, `form-action 'self'`, `frame-ancestors 'none'`; set the policy both in the request headers (Next.js applies the nonce to its own scripts) and in the response headers, and expose the nonce via `x-nonce`.
- **[CONFIGURATION]** A nonce-based CSP requires dynamic rendering (prerendered pages cannot have a per-request nonce): read the nonce with `(await headers()).get('x-nonce')` and pass it to third-party `<Script nonce={nonce}>`s; add `'unsafe-eval'` only if `process.env.NODE_ENV === 'development'`; `'unsafe-inline'` in `script-src` is forbidden.
- **[CONFIGURATION]** Global security headers in `next.config.ts` with `async headers()` on `source: '/:path*'`: `Strict-Transport-Security: max-age=63072000; includeSubDomains; preload`, `X-Content-Type-Options: nosniff`, `Referrer-Policy: strict-origin-when-cross-origin`, `X-Frame-Options: DENY`, `Permissions-Policy: camera=(), microphone=(), geolocation=()`; set `poweredByHeader: false`.
- **[FORBIDDEN]** `dangerouslySetInnerHTML` with unsanitized HTML (CMS, rendered markdown, user input): sanitize with DOMPurify (`isomorphic-dompurify` on the server) via `DOMPurify.sanitize(html, { USE_PROFILES: { html: true } })`, preferably in the Server Component before serializing the string.
- **[SECURITY]** Session cookies set only in Server Actions, Route Handlers, or middleware/proxy with `(await cookies()).set(name, value, { httpOnly: true, secure: true, sameSite: 'lax', path: '/', maxAge })` and the `__Host-` prefix; storing tokens in `localStorage`/`sessionStorage` or in cookies readable by JavaScript is forbidden.
- **[SECURITY]** Open redirect prevention: validate every `callbackUrl`/`next`/`returnTo` before `redirect()`, accepting only relative paths that start with `/` and not with `//` or `/\`, and verifying `new URL(value, origin).origin === origin`; alternatively use an allowlist of destinations.
- **[SECURITY]** Route Handlers (`app/**/route.ts`): export only the needed methods (the others automatically get 405), verify authentication and authorization in every handler, validate query and body with Zod, and respond with `Response.json(body, { status })` without stack traces; for webhooks verify the HMAC signature with `crypto.timingSafeEqual` on the raw body (`await request.text()`).
- **[SECURITY]** CSRF: Server Actions accept only POST and compare the `Origin` header with `Host`; behind a reverse proxy configure `experimental.serverActions.allowedOrigins` with only the known domains; cookie-authenticated POST/PUT/DELETE Route Handlers must verify `Origin` or an anti-CSRF token.
- **[CONFIGURATION]** Keep `experimental.serverActions.bodySizeLimit` at the default (1 MB) or at an explicit reduced value; for large uploads use a dedicated Route Handler or direct upload to storage with signed URLs.
- **[SECURITY]** Errors: in production Next.js replaces the message of server errors with a `digest`; actions must not return raw `error.message`s, stacks, or SQL details, but domain codes (`'FORBIDDEN'`, `'VALIDATION_ERROR'`), logging the details on the server.
- **[SECURITY]** Rate limiting per IP and per user on login, sign-up, password reset, email sending, and expensive actions (e.g. `@upstash/ratelimit` or a limiter at the gateway), with a 429 response and neutral messages that do not reveal whether an account exists.
- **[CONFIGURATION]** Supply chain: `npm audit --omit=dev` or Dependabot/Renovate in CI, committed lockfile with `npm ci` in the pipeline, and prompt updates of `next`, `react`, and `react-dom` to security patches (e.g. CVE-2025-29927 on middleware and CVE-2025-55182 on React Server Components, December 2025).
- **[TESTING]** Mandatory security tests for every action and Route Handler: rejection without a session, with invalid input, and on another user's or tenant's resource; Playwright tests that verify the presence of `content-security-policy` and `strict-transport-security` in the response and the absence of `x-powered-by`.
- **[REFERENCE]** See `references/nextjs-security-hardening.md` for reference anti-patterns and best practices.

### 5. React Performance Optimization and Core Web Vitals (`react-performance-optimization`)

*Scope:* React 19 and Next.js performance optimization: less client JS, next/dynamic, next/image, next/font, React Compiler, memoization only when measured, stable keys, virtualization, useTransition/useDeferredValue, Context without cascading re-renders, bundle analyzer, and Core Web Vitals budgets (LCP, INP, CLS).

- **[PERFORMANCE]** Core Web Vitals budgets at the 75th percentile of field data: LCP < 2.5 s, INP < 200 ms, CLS < 0.1; collect real metrics with `useReportWebVitals` from `next/web-vitals` in a Client Component mounted in the root layout and send them with `navigator.sendBeacon`.
- **[ARCHITECTURE]** Reduce client JavaScript: Server Components by default, `'use client'` only on interactive leaves, heavy libraries (markdown, syntax highlighting, date and currency formatting) used only on the server; check each route's "First Load JS" in the `next build` output and set a budget for it (e.g. ≤ 170 kB gzip per route).
- **[PATTERN]** Load heavy client components not needed for the first paint (rich text editors, charts, maps, complex modals) with `next/dynamic`: `dynamic(() => import('./chart').then((m) => m.Chart), { loading: () => <ChartSkeleton /> })`; the `ssr: false` option is allowed only inside a Client Component.
- **[MANDATORY]** Images only with `next/image`: explicit `width`/`height` (or a static import) or `fill` in a sized container to avoid CLS, accurate `sizes` for responsive images (e.g. `sizes="(max-width: 768px) 100vw, 50vw"`), `priority` on the LCP image (in Next 16 `priority` is deprecated in favor of `preload`); never lazy loading on the LCP element.
- **[CONFIGURATION]** In `next.config.ts` set `images.formats: ['image/avif', 'image/webp']` and `images.remotePatterns` with explicit `hostname` and `pathname` (never `hostname: '**'`), so the optimizer does not become an open proxy.
- **[MANDATORY]** Fonts only with `next/font/google` or `next/font/local` (automatic self-hosting and fallback with `size-adjust`, hence no CLS): `display: 'swap'`, `subsets: ['latin']`, `variable: '--font-sans'`; `<link>`s to fonts.googleapis.com and font `@import`s in CSS are forbidden.
- **[CONFIGURATION]** React Compiler: `reactCompiler: true` in Next 16 (in Next 15 `experimental.reactCompiler: true`) with `babel-plugin-react-compiler` installed; when it is active do not add manual `useMemo`, `useCallback`, or `React.memo` and respect the Rules of React, verified by the compiler rules included in `eslint-plugin-react-hooks`.
- **[FORBIDDEN]** Without React Compiler, applying `useMemo`/`useCallback`/`memo` "just in case": use them only when the React DevTools Profiler shows commits > 16 ms or to stabilize props and dependencies of already-memoized components, documenting the measurement in a comment.
- **[FORBIDDEN]** `key={index}` or `key={Math.random()}` on filterable, sortable, or stateful lists: use stable domain IDs; unstable keys cause remounts, loss of state, and loss of focus.
- **[PATTERN]** Virtualize long lists (> 200 rows or wide grids) with `@tanstack/react-virtual` (`useVirtualizer` with `estimateSize` and `overscan`) or paginate on the server; never thousands of DOM nodes rendered at once.
- **[PATTERN]** For INP use `useTransition`/`startTransition` for non-urgent updates (filters, tabs, sorting) and `useDeferredValue` to derive expensive results from typed text while keeping the input responsive; split event handlers that exceed 50 ms (long tasks).
- **[PATTERN]** Context: split by domain (theme, session, cart) and separate state and actions into distinct contexts with a stable `value`; for frequently updated global state use a store with selectors (`useSyncExternalStore`, Zustand with `useStore(selector)`), so only the affected consumers re-render.
- **[FORBIDDEN]** Derived state synchronized with `useEffect` + `setState` (double render and inconsistent data): compute it during render; move state down to the lowest component that uses it instead of keeping it at the top of the tree.
- **[PERFORMANCE]** CLS: reserve space for async content with identically sized skeletons, `aspect-ratio`, or `min-height`; no banners, cookie bars, or ads injected above the content after load, unless as an overlay.
- **[FORBIDDEN]** Imports from huge barrel files or entire libraries (`import _ from 'lodash'`, `import * as Icons from 'react-icons/md'`): import by path or add the package to `experimental.optimizePackageImports`.
- **[PERFORMANCE]** Third-party scripts with `next/script` and `strategy="lazyOnload"` or `"afterInteractive"`, or with the `@next/third-parties` components (`GoogleTagManager`, `YouTubeEmbed`); never synchronous `<script>`s in `<head>`.
- **[CONFIGURATION]** Bundle analysis with `@next/bundle-analyzer` enabled by `ANALYZE=true`; in Next 16 Turbopack is the default bundler and the analyzer is webpack-based, so generate the report with `ANALYZE=true next build --webpack`.
- **[TESTING]** Budgets verified in CI with Lighthouse CI (`@lhci/cli`): assertions `largest-contentful-paint` ≤ 2500, `cumulative-layout-shift` ≤ 0.1, and `total-blocking-time` ≤ 200 (lab proxy for INP) on the main routes; a First Load JS regression > 10% blocks the PR.
- **[REFERENCE]** See `references/react-performance-optimization.md` for reference anti-patterns and best practices.

### 6. React and Next.js Testing Strategy (`react-testing-strategy`)

*Scope:* Testing strategy for React 19 and Next.js: React Testing Library with role queries, userEvent, MSW for the network, Server Actions tested as functions, async Server Components with Playwright, axe for accessibility, no massive snapshots, coverage thresholds, and deterministic tests.

- **[ARCHITECTURE]** Test pyramid: unit tests for pure functions, Zod schemas, reducers, and hooks; integration tests of Client Components with React Testing Library + MSW (the largest share); Playwright e2e tests for critical flows (login, checkout, main CRUD) and for all pages with async Server Components.
- **[MANDATORY]** RTL queries via `screen` in priority order: `getByRole` with `name` (`screen.getByRole('button', { name: /save/i })`), `getByLabelText`, `getByText`; `getByTestId` only when no role or accessible text exists.
- **[MANDATORY]** Interactions with `@testing-library/user-event` v14: `const user = userEvent.setup()` before `render` and `await user.click()`, `await user.type()`, `await user.keyboard('{Enter}')`; `fireEvent` to simulate the user is forbidden, because it does not generate the realistic sequence of focus, pointer, and keyboard events.
- **[FORBIDDEN]** Testing implementation details: internal state, CSS class names, `container.querySelector`, number of renders, hook calls, or children's props; assert only what the user perceives (text, roles, `toBeDisabled`, `toHaveAccessibleName`, `toHaveAttribute('aria-invalid', 'true')`).
- **[FORBIDDEN]** `toMatchSnapshot()` on whole pages or components: massive snapshots get updated without review; only small `toMatchInlineSnapshot()`s on stable output are allowed (e.g. serialized error messages).
- **[PATTERN]** Asynchrony: `await screen.findByRole(...)` or `await waitFor(() => { expect(...) })` for UI that changes after network calls; `queryBy*` only to assert that an element is absent; no side effects inside `waitFor`.
- **[FORBIDDEN]** Arbitrary waits (`setTimeout`, `sleep`, `page.waitForTimeout()`), dependence on execution order, and mutable data shared between tests: control time with `vi.useFakeTimers({ shouldAdvanceTime: true })` and `vi.setSystemTime()` (with `userEvent.setup({ advanceTimers: vi.advanceTimersByTime })`) or with `page.clock` in Playwright.
- **[MANDATORY]** Network mocked with MSW 2: handlers with `http.get`/`http.post` and `HttpResponse.json()` from `msw`, `setupServer()` from `msw/node` with `server.listen({ onUnhandledRequest: 'error' })` in `beforeAll`, `server.resetHandlers()` in `afterEach`, and `server.close()` in `afterAll`, per-test overrides with `server.use()`; replacing `global.fetch` by hand is forbidden.
- **[PATTERN]** Server Actions tested as async functions: `vi.mock('server-only', () => ({}))`, `vi.mock('next/cache')`, session and repository mocks; build a real `FormData` and verify the typed result for a missing session, invalid input, another tenant's resource, and the success case with `revalidateTag` called on the expected tag.
- **[PATTERN]** Async Server Components are not supported by Vitest/RTL: do not use `render(await Page(...))`; cover them with Playwright and unit-test the Data Access Layer, the DTO mappers, and the leaf Client Components.
- **[MANDATORY]** Automated accessibility: in e2e `new AxeBuilder({ page }).withTags(['wcag2a', 'wcag2aa', 'wcag21a', 'wcag21aa', 'wcag22aa']).analyze()` with `expect(results.violations).toEqual([])` on every key page; in unit tests `vitest-axe` or `jest-axe` with `toHaveNoViolations()` on complex components (dialog, combobox, form).
- **[PATTERN]** Playwright: semantic locators (`page.getByRole`, `page.getByLabel`), web-first assertions with auto-retry (`await expect(locator).toBeVisible()`, `toHaveURL`, `toHaveText`), `baseURL` and `webServer` in `playwright.config.ts` on `next build && next start`, authentication reused via a setup project and `storageState`.
- **[CONFIGURATION]** Vitest: `environment: 'jsdom'`, `globals: true` (needed for RTL's automatic cleanup, otherwise add `afterEach(cleanup)`), `setupFiles: ['./vitest.setup.ts']` with `import '@testing-library/jest-dom/vitest'`, the `@vitejs/plugin-react` and `vite-tsconfig-paths` plugins for the `@/` alias, `clearMocks: true`.
- **[CONFIGURATION]** Coverage with `@vitest/coverage-v8` and blocking `coverage.thresholds` in CI (e.g. `{ lines: 80, functions: 80, statements: 80, branches: 75 }`), excluding generated files, `*.config.*`, `app/**/page.tsx`, and `app/**/layout.tsx` already covered by e2e tests.
- **[PATTERN]** A `renderWithProviders()` helper that mounts the real providers (a new `QueryClient` per test with `retry: false`, theme, i18n) instead of mocking every hook; no state shared between one test and the next.
- **[TESTING]** Every bug fix includes a regression test that fails before the fix; test names describe the expected behavior (`it('shows an error if the email is already registered')`), never `it('works')`.
- **[CONFIGURATION]** Playwright in CI: `forbidOnly: !!process.env.CI`, `retries: process.env.CI ? 2 : 0`, `trace: 'on-first-retry'`; a test that passes only on retry is flaky and must be fixed or quarantined with a ticket, not silenced with `test.skip`.
- **[REFERENCE]** See `references/react-testing-strategy.md` for reference anti-patterns and best practices.

### 7. WCAG 2.2 AA-Compliant React Accessibility (`react-accessibility-wcag`)

*Scope:* WCAG 2.2 AA accessibility for React and Next.js: semantic HTML, associated labels, ARIA only when needed, focus management and dialogs, keyboard, contrast, aria-live for async messages, prefers-reduced-motion, and eslint-plugin-jsx-a11y in CI. Use it for every UI component, form, modal, or navigation.

- **[MANDATORY]** Target WCAG 2.2 level AA conformance, including the criteria introduced in 2.2: 2.4.11 Focus Not Obscured (Minimum), 2.5.7 Dragging Movements, 2.5.8 Target Size (Minimum) with targets ≥ 24×24 CSS px, 3.2.6 Consistent Help, 3.3.7 Redundant Entry, and 3.3.8 Accessible Authentication (Minimum).
- **[ARCHITECTURE]** Semantic HTML first: `<header>`, `<nav aria-label="…">` landmarks, a single `<main id="main-content">`, `<footer>`; one `<h1>` per page and headings without skipped levels; lists with `<ul>`/`<ol>`; data tables with `<caption>` and `<th scope="col">`/`<th scope="row">`.
- **[FORBIDDEN]** `<div onClick>` or `<span onClick>` as controls and `<a>` without `href` or with `href="#"` to perform actions: use `<button type="button">` for actions and `<Link href>`/`<a href>` for navigation, so focus, role, and activation with `Enter`/`Space` are native.
- **[MANDATORY]** Every field has an associated `<label htmlFor>` (ids generated with `useId()` in reusable components); `placeholder` does not replace the label; related radios and checkboxes sit in a `<fieldset>` with a `<legend>`; correct `autoComplete` (`email`, `new-password`, `current-password`, `one-time-code`) for 1.3.5 and 3.3.8.
- **[MANDATORY]** Validation errors: `aria-invalid="true"` on the field, a text message linked with `aria-describedby` (never just color or a red border, 1.4.1) and, after a failed submit, focus moved to the first invalid field or to an error summary with links to the fields.
- **[PATTERN]** First rule of ARIA: use ARIA only when native HTML is not enough; never `role="button"` on a `div` if it can be a `<button>`; for composite widgets (tabs, combobox, listbox, menu) implement the entire ARIA APG pattern (roles, states, keyboard) or use tested libraries such as React Aria or Radix UI.
- **[PATTERN]** Dialogs: prefer the native `<dialog>` element opened with `showModal()` (top layer, underlying content inert, closing with `Escape`, focus restored on close) with `aria-labelledby` on the title; for custom modals guarantee initial focus in the dialog, a focus trap, closing with `Escape`, and focus returning to the element that opened it.
- **[MANDATORY]** Full keyboard operability: every control is reachable with `Tab` in a logical order consistent with the DOM and activatable with `Enter`/`Space`; `tabIndex` > 0 is forbidden; `tabIndex={-1}` only for programmatic focus targets (headings, error summaries).
- **[MANDATORY]** Focus always visible: `outline: none` without an alternative is forbidden; use `:focus-visible` with an indicator ≥ 2 px at contrast ≥ 3:1 and `scroll-padding-top` equal to the height of sticky headers, so the focused element is not covered (2.4.11).
- **[MANDATORY]** Contrast: normal text ≥ 4.5:1, large text (≥ 24 px, or ≥ 18.66 px bold) ≥ 3:1, input borders, icons, and charts ≥ 3:1 (1.4.11); verify the design system tokens in both light and dark mode.
- **[PATTERN]** Async messages (save results, toasts, result counts, Server Action errors) in a live region already present in the DOM before the update: `role="status"` (polite) for informational results, `role="alert"` only for blocking errors; do not mount the region together with the message, otherwise many screen readers do not announce it.
- **[PATTERN]** App Router navigation: the Next.js route announcer reads `document.title` (then the first `h1`) on every client navigation, so every page defines a unique `metadata.title`; add a "Skip to content" skip link pointing to `#main-content` as the first element of `<body>`.
- **[MANDATORY]** Images and icons: descriptive `alt` for informative images and `alt=""` for decorative ones; icon-only buttons with `aria-label` (or `sr-only` text) and inner SVGs with `aria-hidden="true"`; toggle state exposed with `aria-pressed` or `aria-expanded`.
- **[PATTERN]** Motion: disable non-essential animations and transitions with `@media (prefers-reduced-motion: reduce)` or Motion's `useReducedMotion()`; no automatically moving content for more than 5 s without a pause control (2.2.2) and no flashing more than 3 times per second (2.3.1).
- **[MANDATORY]** `<html lang="en">` (the site's primary language) in the root layout and a `lang` attribute on portions in another language; a layout that withstands 200% zoom and reflow at 320 CSS px without horizontal scrolling (1.4.10); `maximum-scale=1` and `user-scalable=no` in the viewport are forbidden.
- **[FORBIDDEN]** Drag-only interactions (reordering, custom sliders, uploads) without a single-pointer or keyboard alternative (2.5.7) and interactive targets smaller than 24×24 CSS px without sufficient spacing (2.5.8).
- **[CONFIGURATION]** `eslint-plugin-jsx-a11y` in flat config with the `jsxA11y.flatConfigs.strict` preset (if `eslint-config-next` already registers the `jsx-a11y` plugin, add only `jsxA11y.flatConfigs.strict.rules` to avoid the plugin redefinition error), `settings: { 'jsx-a11y': { components: { Button: 'button', TextField: 'input' } } }` for design system components, and a blocking `eslint . --max-warnings=0` in CI.
- **[TESTING]** Multi-level checks: RTL `getByRole(..., { name })` queries as an implicit check of accessible names; `@axe-core/playwright` with the `wcag22aa` tag on every key page; keyboard tests in Playwright (`page.keyboard.press('Tab')`, `expect(locator).toBeFocused()`); manual testing with NVDA or VoiceOver on critical flows before release.
- **[REFERENCE]** See `references/react-accessibility-wcag.md` for reference anti-patterns and best practices.
