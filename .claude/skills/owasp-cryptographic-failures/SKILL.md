# Skill: Cryptographic Failures (OWASP A02:2021)

## Implementation Rules:
- **[ARCHITECTURE]** Classify data before choosing the cryptography: credentials, PANs, identity documents, health data and GDPR special categories (Art. 9), tokens and secrets; for each class define protection in transit, at rest, in logs/backups, and retention, and minimize what is stored.
- **[MANDATORY]** TLS 1.2+ (preferably 1.3) on all connections, including internal ones to DBs, brokers, and microservices, with AEAD cipher suites and forward secrecy (ECDHE + AES-GCM or ChaCha20-Poly1305); HSTS `max-age=31536000; includeSubDomains`; DB drivers with full verification (PostgreSQL `sslmode=verify-full`, MySQL `sslMode=VERIFY_IDENTITY`).
- **[FORBIDDEN]** Disabling certificate verification: Python `verify=False`, `ssl._create_unverified_context()`, `ssl.CERT_NONE`, `check_hostname = False`; Node `rejectUnauthorized: false`, `NODE_TLS_REJECT_UNAUTHORIZED=0`; Java `X509TrustManager` with an empty `checkServerTrusted`, a `HostnameVerifier` that returns `true`, `NoopHostnameVerifier`, `TrustAllStrategy`; for internal CAs configure a truststore, `verify="/path/ca.pem"`, or the `ca` option.
- **[FORBIDDEN]** MD5 and SHA-1 for any security purpose (signatures, integrity, HMAC in new systems, passwords, token derivation); allowed only for non-security checksums declared as such (Python ≥ 3.9 `hashlib.md5(data, usedforsecurity=False)`); use SHA-256/384/512, SHA-3, and HMAC-SHA-256.
- **[MANDATORY]** Symmetric encryption with AES-256-GCM (or ChaCha20-Poly1305) with a 96-bit nonce unique per key (random from a CSPRNG within 2^32 encryptions per key, or a counter), a 128-bit tag, AAD binding the ciphertext to its context (`tenant_id|record_id|field`), and a versioned format `version || nonce || ciphertext || tag`: Java `Cipher.getInstance("AES/GCM/NoPadding")` + `GCMParameterSpec(128, nonce)`, Python `cryptography` `AESGCM`, Node `createCipheriv('aes-256-gcm', key, nonce)` + `getAuthTag()`/`setAuthTag()`.
- **[FORBIDDEN]** ECB mode (in Java `Cipher.getInstance("AES")` is equivalent to `AES/ECB/PKCS5Padding`), CBC without a MAC (padding oracle), static IVs/nonces or ones derived from the key, nonce reuse in GCM (compromises confidentiality and authenticity), DES/3DES/RC4/Blowfish, RSA < 2048 bits, RSA PKCS#1 v1.5 for encryption (use OAEP with SHA-256).
- **[FORBIDDEN]** Keys, secrets, IVs, or peppers hardcoded in code or in versioned files (`new SecretKeySpec("0123456789abcdef".getBytes(), "AES")`, `SECRET_KEY = "changeme"`, committed `.env` files), even in test branches (CWE-321/CWE-798).
- **[MANDATORY]** Key management with a KMS (AWS KMS, Azure Key Vault, GCP Cloud KMS) or HashiCorp Vault Transit: envelope encryption with a DEK per record or table encrypted by the KEK, the key version identifier stored with the ciphertext, planned rotation (e.g. yearly KEK, progressive re-encryption), documented revocation, and separation of duties between DB administrators and key administrators.
- **[MANDATORY]** CSPRNG for every security value (tokens, session IDs, nonces, salts, OTPs, API keys, reset links): Java `SecureRandom`, Python `secrets.token_bytes`/`token_urlsafe`/`randbelow`, Node `crypto.randomBytes`/`randomUUID`/`randomInt`; `java.util.Random`, `Math.random()`, `ThreadLocalRandom`, Python's `random` module, and UUID v1 are forbidden (CWE-338).
- **[MANDATORY]** Constant-time comparison of secrets: Java `MessageDigest.isEqual(a, b)`, Python `hmac.compare_digest(a, b)`, Node `crypto.timingSafeEqual(a, b)` after verifying that the two `Buffer`s have the same length (otherwise it throws); applies to webhook HMAC signatures, API keys, tokens, and OTP codes, never `equals`, `==`, or `===` (CWE-208).
- **[FORBIDDEN]** Home-made cryptography: XOR, Base64, or ROT13 as "encryption", custom algorithms, MACs built as `sha256(secret + message)` (vulnerable to length extension: use HMAC), keys derived with `sha256(password)` (use HKDF for high-entropy material, Argon2id/PBKDF2 for passwords).
- **[MANDATORY]** At-rest encryption: volume/DB encryption (TDE, RDS/EBS encryption) as a baseline, plus application-level field encryption for high-risk data (PANs, rendered unreadable per PCI DSS v4.0 req. 3.5.1; identity documents; health data); for searches on encrypted fields use an HMAC-SHA-256 blind index with a distinct key, never unsalted hashes of low-entropy data.
- **[SECURITY]** No sensitive data in plaintext in URLs, HTTP caches (`Cache-Control: no-store` on responses with personal data), logs, error messages, or unencrypted backups; a signed JWT's payload is just Base64URL and must not contain PII or secrets.
- **[REVIEW]** Grep: `MessageDigest\.getInstance\("(MD5|SHA-?1)"`, `hashlib\.(md5|sha1)\(`, `createHash\(['"](md5|sha1)`, `Cipher\.getInstance\("(AES|DES|DESede)"\)`, `/ECB/`, `aes-\d+-ecb`, `createCipher\(` (without IV, removed in Node.js 22), `new Random\(|Math\.random\(|random\.(random|randint|choice)`, `verify\s*=\s*False`, `rejectUnauthorized:\s*false`, `NODE_TLS_REJECT_UNAUTHORIZED`, `SecretKeySpec\(".*"\.getBytes`, `BEGIN (RSA |EC )?PRIVATE KEY`.
- **[PERFORMANCE]** AES-GCM takes advantage of AES-NI: do not replace it with "lightweight" alternatives; at high volumes use envelope encryption with a short-TTL local DEK cache (e.g. AWS Encryption SDK caching CMM) instead of one KMS call per record; in Java avoid `SecureRandom.getInstanceStrong()` on hot paths of Linux servers (it can block waiting for entropy) and use `new SecureRandom()`.
- **[TESTING]** Automated tests: encryption/decryption round trip; decryption that fails with an altered tag, nonce, or AAD (`AEADBadTagException`, `InvalidTag`); two encryptions of the same plaintext produce different ciphertexts; a connection to a test server with a self-signed certificate or wrong hostname that must fail; endpoint scanning with `testssl.sh` or `sslyze` in CI.
- **[CONFIGURATION]** Explicit minimum TLS version: Spring Boot `server.ssl.enabled-protocols=TLSv1.3,TLSv1.2`, Java `jdk.tls.disabledAlgorithms` with SSLv3, TLSv1, TLSv1.1, RC4, DES, 3DES_EDE_CBC; Node `minVersion: 'TLSv1.2'` or `tls.DEFAULT_MIN_VERSION`; Python `ctx = ssl.create_default_context()` with `ctx.minimum_version = ssl.TLSVersion.TLSv1_2`.
- **[SECURITY]** Crypto agility: store the algorithm and key version together with the ciphertext to enable migrations (rotation, new algorithms, post-quantum hybrid schemes) without decrypting everything in a single operation.
- **[CWE]** CWE-327, CWE-328, CWE-326, CWE-321, CWE-323 (nonce reuse), CWE-329, CWE-330/CWE-338, CWE-319, CWE-916 → A02:2021; CWE-295 (certificate verification) and CWE-798 are officially mapped to A07:2021; CWE-208 for non-constant-time comparisons.
- **[REFERENCE]** See `EXAMPLES.md` in this folder for reference anti-patterns and best practices.
