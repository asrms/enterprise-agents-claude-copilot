# Skill: Asynchrony, Cancellation, and Concurrency

## Implementation Rules:
- **[MANDATORY]** Use `async`/`await` with `try/catch` at the point where the error can actually be handled (UI or feature boundary); nested `.then()` chains and mixing `await` with `.then()` in the same function are forbidden.
- **[FORBIDDEN]** Floating promises: every Promise is awaited with `await`, returned to the caller, or terminated with `.catch()`; intentional fire-and-forget is written as `void task().catch(reportError)` (global `reportError()`: Chrome 95+, Firefox 93+, Safari 15.4+).
- **[FORBIDDEN]** `items.forEach(async (item) => { await save(item); })` and async callbacks passed to APIs that ignore the returned Promise: use `for...of` with `await` for sequential execution or `Promise.all(array.map(fn))` for parallel execution.
- **[FORBIDDEN]** Async executors `new Promise(async (resolve) => resolve(await load()))` (thrown exceptions are lost) and `throw 'string'` or `reject('string')`: always throw `Error` instances, with a stack trace.
- **[PATTERN]** Choose the combinator by semantics: `Promise.all` when you need every result (fail-fast), `Promise.allSettled` when partial results are useful (dashboard widgets, multiple submissions), iterating on `status === 'fulfilled'`/`'rejected'`, `Promise.any` for the first success, `Promise.race` only paired with cancellation of the losing operations.
- **[PERFORMANCE]** Start independent operations in parallel with `const [user, orders] = await Promise.all([getUser(signal), getOrders(signal)])` instead of sequential `await`s; never create a promise and leave it waiting for a later `await`, because an early rejection becomes an `unhandledrejection`.
- **[MANDATORY]** Every `fetch` has a timeout and cancellation: `AbortSignal.timeout(ms)` (Chrome 103+, Firefox 100+, Safari 16+) combined with the caller's signal via `AbortSignal.any([signal, AbortSignal.timeout(8000)])` (Chrome 116+, Firefox 124+, Safari 17.4+; for older browsers, fall back to `AbortController` and `setTimeout`).
- **[MANDATORY]** Classify errors: `DOMException` with `name === 'AbortError'` (intentional cancellation: ignore it with no logging and no UI message), `name === 'TimeoutError'` (from `AbortSignal.timeout()`: timeout message, retry allowed), `TypeError` (network error), `!response.ok` (fetch does not reject on 4xx/5xx: throw an `HttpError` with `status`).
- **[PATTERN]** Latest-wins race condition handling for searches, filters, and navigation: on every new request call `abort()` on the previous controller and apply to the DOM only the response of the current request, comparing the controller or an incremental `requestId`.
- **[PATTERN]** Deduplicate identical in-flight requests with a `Map<string, Promise>` (single-flight), removing the key in `finally`, so multiple components requesting the same resource share a single fetch.
- **[PATTERN]** Retry only on transient errors (network, timeout, HTTP 408, 429, 500, 502, 503, 504) and on idempotent requests (GET, PUT, DELETE, or POST with an `Idempotency-Key` header); exponential backoff with full jitter `Math.random() * Math.min(maxDelayMs, baseDelayMs * 2 ** attempt)`, at most 3-5 attempts, honor the `Retry-After` header, and make the wait interruptible by the `signal`.
- **[PATTERN]** Enrich errors without losing the original: `throw new Error('Failed to load orders', { cause: error })` (ES2022); domain errors such as `class HttpError extends Error` with `name`, `status`, and non-sensitive diagnostic data.
- **[PATTERN]** Limit the concurrency of uploads, bulk fetches, and heavy tasks with a pool of N async workers (4-6 for the same origin), never `Promise.all` over hundreds of simultaneous requests; the pool accepts a `signal` and returns results in `PromiseSettledResult` format.
- **[PATTERN]** Use `Promise.withResolvers()` (ES2024: Chrome 119+, Firefox 121+, Safari 17.4+) for externally resolved promises (worker handshake, waiting for an event) instead of hand-captured `let resolve` variables.
- **[MANDATORY]** Register `window.addEventListener('unhandledrejection', handler)` and `window.addEventListener('error', handler)` in the composition root to send escaped rejections to telemetry with `navigator.sendBeacon()`; they are a safety net and do not replace local handling.
- **[SECURITY]** Before sending errors to telemetry, strip tokens, `Authorization` headers, query strings with personal data, and PII from `message` and `cause`; always-present timeouts prevent hanging requests that exhaust connections and memory.
- **[TESTING]** Test retry, backoff, and timeouts with `vi.useFakeTimers()` and `await vi.advanceTimersByTimeAsync(ms)`; `Math.random` and the wait function are injectable or mocked (`vi.spyOn(Math, 'random').mockReturnValue(0.5)`) to make the jitter deterministic; the abort path has a dedicated test (no DOM update after `abort()`).
- **[CONFIGURATION]** ESLint: `no-async-promise-executor`, `prefer-promise-reject-errors`, `require-atomic-updates`, `no-await-in-loop` as `warn` (can be disabled line by line with a justified comment when sequential execution is intentional); with type-aware linting on `checkJs`, enable `@typescript-eslint/no-floating-promises`.
