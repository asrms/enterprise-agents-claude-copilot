# Skill: Testing with Vitest and Testing Library

## Implementation Rules:
- **[CONFIGURATION]** `vitest.config.js` with `defineConfig` imported from `vitest/config`: `environment: 'happy-dom'` (faster) or `'jsdom'` (more faithful for forms and CSS), `setupFiles: ['./test/setup.js']`, `include: ['src/**/*.test.js']`, `restoreMocks: true`, and `unstubGlobals: true`.
- **[CONFIGURATION]** Coverage with `@vitest/coverage-v8`: `coverage: { provider: 'v8', include: ['src/**/*.js'], exclude: ['src/**/*.test.js', 'src/main.js'], thresholds: { lines: 80, functions: 80, statements: 80, branches: 75 } }`; CI runs `npx vitest run --coverage` and fails below the threshold.
- **[CONFIGURATION]** In `test/setup.js` import `@testing-library/jest-dom/vitest` for the matchers `toBeInTheDocument()`, `toBeEnabled()`, `toHaveAccessibleName()`, and `toHaveTextContent()`; files that test only pure logic declare `// @vitest-environment node` at the top.
- **[ARCHITECTURE]** Tests co-located next to the module (`cart-store.js` and `cart-store.test.js`); `describe` with the name of the public unit and `it` describing in English the expected behavior and the condition (`it('returns the total in cents when the cart contains discounts')`).
- **[MANDATORY]** Arrange-Act-Assert structure with the three phases separated by a blank line or comment, a single behavior per `it`, no conditional logic or loops in tests; table cases use `it.each(cases)` with an explicit table of inputs and expected outputs.
- **[PATTERN]** Pure logic (reducers, selectors, formatters, validators) tested without DOM or mocks: explicit inputs and output checked with `toEqual`/`toBe`; it is the level with the most tests and the fastest in the pyramid.
- **[MANDATORY]** @testing-library/dom queries in priority order: `getByRole(container, 'button', { name: 'Save' })`, then `getByLabelText`, `getByText`, and only as a last resort `getByTestId`; `querySelector` with CSS classes or structural selectors (`tr:nth-child(2) td`) is forbidden.
- **[MANDATORY]** User interactions with `@testing-library/user-event` (`const user = userEvent.setup(); await user.type(input, 'shoes')`) instead of manual `dispatchEvent` or `fireEvent`, which do not reproduce focus, the `keydown`/`keyup` sequence, and `input`.
- **[FORBIDDEN]** Testing private details: `#private` fields, `_internal` properties, non-exported functions, the number of calls to internal helpers, or DOM structure the user cannot perceive; snapshots of the entire `document.body.innerHTML` as the only assertion are forbidden.
- **[PATTERN]** Controlled time: `vi.useFakeTimers()` in `beforeEach` and `vi.useRealTimers()` in `afterEach`; `vi.advanceTimersByTime(ms)` for synchronous code and `await vi.advanceTimersByTimeAsync(ms)` when there are promises between timers (debounce with fetch, retry with backoff); with user-event use `userEvent.setup({ advanceTimers: vi.advanceTimersByTime })`.
- **[FORBIDDEN]** Real waits such as `await new Promise((r) => setTimeout(r, 500))`; with Vitest fake timers do not use Testing Library's `findBy*` or `waitFor`, which only recognize Jest's fake timers and can hang: after advancing time use synchronous `getBy*` queries or `vi.waitFor()`.
- **[PATTERN]** Network mocks in unit tests: a fake `fetchFn` injected via factory or `vi.spyOn(globalThis, 'fetch').mockResolvedValue(new Response(JSON.stringify(data), { status: 200, headers: { 'Content-Type': 'application/json' } }))` with real `Response` objects; never fake objects with only a `json()` method and no `ok`, `status`, and `headers`.
- **[PATTERN]** Integration tests with MSW: `setupServer(http.get('https://api.acme.test/cart', () => HttpResponse.json(data)))` imported from `msw/node`, `server.listen({ onUnhandledRequest: 'error' })` in `beforeAll`, `server.resetHandlers()` in `afterEach`, `server.close()` in `afterAll`, and per-test overrides with `server.use()`.
- **[MANDATORY]** Cleanup in `afterEach`: `document.body.replaceChildren()` (@testing-library/dom does not clean up automatically), `abort()` of mounted components' controllers, `vi.restoreAllMocks()` and `vi.unstubAllGlobals()` if not configured globally; every test must pass on its own and in random order (`sequence: { shuffle: true }`).
- **[TESTING]** Error and cancellation paths verified explicitly: `await expect(promise).rejects.toThrow('Loading orders failed')`, `await expect(promise).rejects.toHaveProperty('cause', expect.any(HttpError))` and, after `controller.abort()`, no DOM updates; `expect.assertions(n)` when assertions live in async callbacks.
- **[SECURITY]** XSS regression tests on views that render external data: with the input `<img src=x onerror=alert(1)>` verify `expect(container.querySelector('img')).toBeNull()` and that the text appears literally with `getByText('<img src=x onerror=alert(1)>')`.
- **[PERFORMANCE]** A fast suite: pure logic in the `node` environment, simulated DOM only where needed, Vitest Browser Mode with Playwright reserved for cases that require real layout, `ElementInternals`, or APIs not implemented by jsdom/happy-dom; no real network calls in any test.
- **[FORBIDDEN]** Committed `.only` and `.skip`: enable `@vitest/eslint-plugin` with the rules `vitest/no-focused-tests` and `vitest/no-disabled-tests` in the flat config for `**/*.test.js` files.
- **[REFERENCE]** See `EXAMPLES.md` in this folder for reference anti-patterns and best practices.
