# Skill: Data Fetching and Caching in Next.js App Router

## Implementation Rules:
- **[ARCHITECTURE]** Load data in `async` Server Components through the Data Access Layer (`features/*/server/queries.ts` with `import 'server-only'`), in the component that uses it; never `useEffect` + `fetch` for data available at render time, and never `fetch` to the same project's Route Handlers (`http://localhost:3000/api/...`).
- **[MANDATORY]** Next.js 15+: `fetch` is no longer cached by default and `GET` Route Handlers are dynamic by default; always declare the strategy on every call: `cache: 'force-cache'` (static), `next: { revalidate: 3600, tags: ['products'] }` (ISR with tags), or `cache: 'no-store'` (per-user or real-time data).
- **[MANDATORY]** Next.js 16 with `cacheComponents: true` in `next.config.ts`: use the `'use cache'` directive (at file, component, or function level) with `cacheLife('hours')` and `cacheTag('product:42')` imported from `next/cache`; components that read uncached data or runtime APIs (`cookies()`, `headers()`, `searchParams`) must sit under a `<Suspense>`, otherwise the build-time prerender fails.
- **[FORBIDDEN]** With Cache Components, using `export const revalidate`, `export const dynamic`, or `fetchCache`: replace them with `'use cache'` + `cacheLife`; and calling `cookies()`/`headers()` inside a `'use cache'` function: read them outside and pass the values as arguments, which become part of the cache key (arguments and return value must be serializable).
- **[CONFIGURATION]** Next.js 15 without Cache Components: to cache non-`fetch` queries (ORM, SDK) use `unstable_cache(fn, ['key'], { revalidate, tags })`; in Next 16 migrate to `'use cache'`.
- **[PATTERN]** Independent requests in parallel: start them together with `await Promise.all([...])` (or `Promise.allSettled` for optional sections); chains of sequential `await` on data that does not depend on each other (waterfalls) are forbidden.
- **[PATTERN]** Streaming: isolate slow sections in separate `async` components wrapped in `<Suspense fallback={<Skeleton />}>`, so the shell and the LCP content arrive immediately; `loading.tsx` is the segment-level Suspense boundary.
- **[PATTERN]** For data destined for a Client Component, pass the un-awaited Promise as a prop and consume it with `use(promise)` under `<Suspense>`: streaming starts from the server with no client-side waterfall.
- **[PATTERN]** Deduplicate per request with `React.cache()` the non-`fetch` DAL functions called by `generateMetadata`, layouts, and pages; `GET` `fetch` calls with the same URL and options are already memoized during render.
- **[PATTERN]** Mutations only through Server Actions (`'use server'`) wired to `<form action>`, with `useActionState` (React 19) for result and errors and `useFormStatus` (`react-dom`) for pending state; after the write, invalidate with `revalidateTag`/`revalidatePath` and call `redirect()` outside the `try/catch`, because it throws a control-flow exception.
- **[CONFIGURATION]** Version-dependent `revalidateTag` signature: Next 15 `revalidateTag('orders')`; Next 16 `revalidateTag('orders', 'max')` (`cacheLife` profile for stale-while-revalidate) and `updateTag('orders')` in Server Actions when users must see their own write immediately (read-your-writes).
- **[PATTERN]** `useOptimistic` for immediate feedback on frequent mutations (toggles, likes, reordering), with automatic rollback when the action completes or fails.
- **[ARCHITECTURE]** Client-side TanStack Query only for highly interactive server state (polling, infinite scroll, live filters, cross-tab sync): prefetch on the server with `queryClient.prefetchQuery` + `dehydrate` and `<HydrationBoundary>`, `staleTime` > 0 (e.g., `60_000`) to avoid an immediate refetch after hydration; do not duplicate with TanStack Query data already provided by Server Components.
- **[SECURITY]** Never cache (`force-cache`, `'use cache'`, `unstable_cache`) per-user data unless the identity is part of the key: you risk serving one user's data to others; personal data uses `cache: 'no-store'` or is read at runtime inside `<Suspense>`.
- **[MANDATORY]** `fetch` does not throw on 4xx/5xx: check `res.ok`, validate the body with Zod (`Schema.parse(await res.json())`), map 404 to `null` → `notFound()`, and map other errors to a `throw` caught by `error.tsx`.
- **[PERFORMANCE]** Granular, hierarchical tags (`products`, `product:${id}`, `category:${slug}`) for targeted invalidation; avoid `revalidatePath('/', 'layout')`, which invalidates the entire application.
- **[PERFORMANCE]** Set a timeout on server calls to external services with `signal: AbortSignal.timeout(5000)` and use `after()` from `next/server` (stable since Next 15.1) for logging and analytics after the response is sent, without slowing down streaming.
- **[TESTING]** Test Server Actions as functions with `vi.mock('next/cache')`, asserting that `revalidateTag`/`updateTag` is called with the expected tag; verify streaming, fallbacks, and data freshness after a mutation with Playwright against `next build && next start`, because caching in `next dev` is not representative.
